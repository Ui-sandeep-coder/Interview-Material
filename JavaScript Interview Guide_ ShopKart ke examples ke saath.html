Scope, Hoisting aur Variables 6 sawaal

1Scope in JS (Global, Functional, Block)

What: Scope = wo jagah jahan tak ek variable dikhta aur use ho sakta hai. JS mein 3 main scope hote hain (module scope bhi, jab ES modules use karo).

Scope Kaise banta hai Kaun se variables
Global Poori file/window ke level par var, let, const, functions
Function Har function ke andar var, let, const (function ke bahar nahi dikhte)
Block { } (if, for, while, plain block) Sirf let, const, class

Why: Variables ko apni limit mein rakhne se naming conflicts aur accidental changes nahi hote.

var globalVar = "sab jagah";

function checkout() {
  var fnVar = "sirf checkout ke andar";
  if (true) {
    var a = 1;        // function scope: block ke bahar bhi dikhega
    let b = 2;        // block scope: sirf is { } mein
    const c = 3;
  }
  console.log(a);     // 1
  console.log(b);     // ReferenceError
}

Real bug (ShopKart): for (var i...) loop ke andar var discount likha tha, loop ke bahar bhi dikh raha tha aur galat total aaya. let/const use karne par fix.

Interview line: “Modern JS mein var avoid karte hain kyunki wo block-scoped nahi hota.”

2Scope Chaining

What: Jab JS ko koi variable chahiye, wo pehle current scope mein dhundta hai; nahi mila to bahar wale (parent) scope mein, phir uske bahar… aakhir mein global tak. Is chain ko scope chain kehte hain. Global mein bhi nahi mila to ReferenceError.

const tax = 0.18;                    // global

function cart() {
  const shipping = 50;               // cart scope
  function total(price) {
    const discount = 100;            // total scope
    return price + price * tax + shipping - discount;
    //     ^ price: apna  | tax: global tak gaya | shipping: parent mein mila
  }
  return total(1000);
}

Important: Chain lexical hoti hai (function jahan likha gaya hai wahan se), jahan call hua wahan se nahi (Q57 dekho). Isi chain par closure bana hai. Variable shadowing (Q41) mein chain mein sabse pehle mila variable jeet jata hai.

5Temporal Dead Zone (TDZ)

What: let, const, class ka binding scope shuru hote hi ban jata hai (hoist hota hai), par declaration line tak initialize nahi hota. Scope ki shuruaat se declaration line tak ka time = Temporal Dead Zone. Is dauran access karne par ReferenceError.

{
  // TDZ shuru (b ke liye)
  console.log(b);       // ReferenceError: Cannot access 'b' before initialization
  let b = 5;            // TDZ khatam, b initialize
  console.log(b);       // 5
}

Why aaya: var ka undefined wala silent behaviour bugs chhupata tha. TDZ galti turant pakadta hai.

Proof ki hoisting hoti hai:

let x = "bahar";
{
  console.log(x);   // ReferenceError! (andar wala x hoist hua, bahar wala nahi dikha)
  let x = "andar";
}

Tricky: Default params mein bhi TDZ: function f(a = b, b = 1) {} → f() error. typeof bhi TDZ mein error deta hai (Q55).

Prototypes 3 sawaal

7Prototypes in JS

What: JS mein har object ka ek hidden link hota hai [[Prototype]] jo kisi doosre object ki taraf point karta hai. Property na mile to JS wahan dhundta hai. Isi se inheritance hoti hai (class-based nahi, prototype-based).

Why: Methods ko har object mein copy karne ki jagah ek baar prototype par rakhte hain, memory bachti hai.

const animal = { eats: true, walk() { return "walking"; } };
const dog = Object.create(animal);    // dog.[[Prototype]] = animal
dog.barks = true;

console.log(dog.eats);                // true (prototype se mila)
console.log(dog.walk());              // "walking"
console.log(Object.getPrototypeOf(dog) === animal);   // true
console.log(dog.hasOwnProperty("eats")); // false

Access: Object.getPrototypeOf(obj) (sahi tareeka), obj.__proto__ (purana accessor, production code mein avoid). class bhi andar se prototypes hi hai - sirf syntax sugar.

8Prototype Object (.prototype vs __proto__)

Sabse common confusion:

  • Fn.prototype: Sirf functions (constructors) ke paas hota hai. Ye wo object hai jo us constructor se bane instances ka [[Prototype]] banega.
  • obj.__proto__: Har object ke paas; wo uska actual prototype hai.
function Product(name) { this.name = name; }
Product.prototype.getInfo = function () { return "Product: " + this.name; };

const p = new Product("Shoes");

p.__proto__ === Product.prototype;                  // true
Product.prototype.constructor === Product;          // true
p.getInfo();                                        // method prototype se
Object.getPrototypeOf(Product) === Function.prototype; // true

Memory benefit: 1000 products bane, getInfo ek hi baar memory mein (prototype par), har instance mein copy nahi.

ES6 class mein:

class Product {
  constructor(name) { this.name = name; }
  getInfo() { return this.name; }       // Product.prototype par jata hai
}
9Prototype Chaining

What: Prototype ka bhi prototype hota hai, aur aage bhi… ye chain null par khatam hoti hai. Property lookup chain ke upar chalta hai.

function Animal() {}
Animal.prototype.eat = () => "eating";
function Dog() {}
Dog.prototype = Object.create(Animal.prototype);   // chain jodi
Dog.prototype.constructor = Dog;
Dog.prototype.bark = () => "woof";

const d = new Dog();
d.bark();   // Dog.prototype
d.eat();    // Animal.prototype
d.toString(); // Object.prototype
// Chain: d -> Dog.prototype -> Animal.prototype -> Object.prototype -> null

Lookup rule: Pehle apni own properties, phir chain mein upar. Mili nahi to undefined. Write karte waqt hamesha apne object par property banti hai (prototype par nahi), isse shadowing hoti hai.

Performance: Chain bahut lambi nahi honi chahiye. instanceof isi chain ko check karta hai. for...in chain ki enumerable properties bhi deta hai; Object.keys sirf own.

Real use: Array methods (map, filter) Array.prototype par hain; isi chain se aap array par .toString() bhi call kar sakte ho.

Functions, Closures aur Object Basics 8 sawaal

10Closures

What: Jab ek inner function apne outer function ke variables ko yaad rakhta hai, outer function ke khatam hone ke baad bhi. Function + uska lexical environment = closure.

Why: Private data, state ko save rakhna, function factories, debounce/memoize/once jaise patterns.

function createCart() {
  let items = [];                         // private, bahar se access nahi
  return {
    add: item => { items.push(item); return items.length; },
    count: () => items.length,
  };
}
const cart = createCart();
cart.add("shoes");
cart.count();     // 1
cart.items;       // undefined (private)

Common uses: Data hiding, once(fn), debounce, counters, event handlers, React hooks (useState closure ke through state yaad rakhta hai).

Classic bug:

for (var i = 1; i <= 3; i++) setTimeout(() => console.log(i), 100);  // 4 4 4
// Fix: let use karo, ya IIFE
for (var i = 1; i <= 3; i++) ((j) => setTimeout(() => console.log(j), 100))(i);

Downsides: Zyada closures aur bade objects reference mein rahe to memory leak (Q77). React mein stale closure bug.

11Pass by Reference vs Pass by Value

Truth: JS mein hamesha pass by value hota hai. Fark ye hai ki object ke case mein value = reference (address) ki copy hoti hai. Isse “call by sharing” bhi kehte hain.

function changePrimitive(n) { n = 100; }
let x = 10; changePrimitive(x); console.log(x);   // 10 (copy badli)

function mutate(obj)  { obj.price = 999; }          // same object ko modify
function reassign(obj){ obj = { price: 1 }; }       // sirf local copy ka address badla

const product = { price: 500 };
mutate(product);   console.log(product.price);      // 999
reassign(product); console.log(product.price);      // 999 (original safe)

Takeaway: Function ke andar object ke properties badlo to bahar asar padega; parameter ko naya object assign karo to nahi.

Real bug: applyCoupon(cart) ne cart object ko mutate kar diya, UI update nahi hua (React ko reference same dikha). Fix: naya object return karo { ...cart, total: ... }. Copy ke liye shallow vs deep (P10).

12Currying in JS

What: Ek function jo multiple arguments leta hai usko ek-ek argument wale functions ki chain mein badalna: f(a, b, c) → f(a)(b)(c).

Why: Partial application (kuch args pehle fix karke reusable function banana), function composition, config pehle aur data baad mein.

const add = a => b => c => a + b + c;
add(1)(2)(3);          // 6

// ShopKart: ek baar discount set, baar-baar use
const applyDiscount = percent => price => price - (price * percent) / 100;
const festival = applyDiscount(20);
festival(1000);        // 800
festival(500);         // 400

// Generic curry (fn.length se arguments count)
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}
const sum3 = curry((a, b, c) => a + b + c);
sum3(1)(2)(3);  sum3(1, 2)(3);  sum3(1)(2, 3);   // sab 6

Currying vs Partial application: Currying = hamesha 1-1 argument ki chain. Partial = kuch arguments fix karke baaki ke liye naya function (bind yahi karta hai). Limitation: fn.length default/rest params ko count nahi karta.

13Infinite Currying Problem

Question: sum(1)(2)(3)...() ya sum(1)(2)(3) jaisa jitni baar bhi call karo aur result mile. Number of arguments pata nahi.

Version 1: End mein empty call () se rukta hai (sabse common):

function sum(a) {
  return function (b) {
    if (b === undefined) return a;     // empty call = khatam
    return sum(a + b);
  };
}
sum(1)(2)(3)();     // 6

Version 2: Multiple args bhi allowed sum(1,2)(3)(4,5)():

function sum(...a) {
  const total = a.reduce((x, y) => x + y, 0);
  return (...b) => (b.length ? sum(total, ...b) : total);
}
sum(1, 2)(3)(4, 5)();    // 15

Version 3: Bina () ke, valueOf/toString trick:

function sum(a) {
  const f = b => sum(a + b);
  f.valueOf = () => a;          // jab number context mein aaye (+, ==, console)
  f.toString = () => String(a);
  return f;
}
sum(1)(2)(3) + 0;     // 6 (coercion ke time valueOf chalta hai)

Why ye puchte hain: Closure + recursion + type coercion (Q30) ek saath test hote hain.

14Memoization in JS

What: Function ke result ko cache karna taaki same input par dobara calculation na karni pade. Closure + Map ka use.

Why: Expensive/pure functions (fibonacci, price calculation, filtering) ko speed dena.

function memoize(fn) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);   // hit
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const slowSquare = n => { for (let i = 0; i < 1e8; i++); return n * n; };
const fast = memoize(slowSquare);
fast(9);   // slow, pehli baar
fast(9);   // instant (cache hit)

// Fibonacci: O(2^n) se O(n)
const fib = memoize(n => (n < 2 ? n : fib(n - 1) + fib(n - 2)));

Dhyan: Sirf pure functions par (same input → same output). JSON.stringify key objects/functions ke saath galat ho sakti hai. Cache unlimited badhta hai, to LRU/TTL (P12). React mein useMemo, React.memo isi idea par hain.

15Rest Parameter

What: ...name syntax jo function ke bache hue arguments ko ek real array mein collect karta hai. Sirf last parameter ho sakta hai.

function addToCart(user, ...items) {
  console.log(user);    // "Riya"
  console.log(items);   // ["shoes", "bag", "watch"] (real array)
}
addToCart("Riya", "shoes", "bag", "watch");

const total = (...nums) => nums.reduce((a, b) => a + b, 0);
total(1, 2, 3, 4);   // 10

const [first, ...others] = [1, 2, 3];       // destructuring mein bhi
const { id, ...rest } = { id: 1, a: 2, b: 3 }; // rest = { a: 2, b: 3 }

arguments se difference: arguments array-like hai (map/filter nahi), arrow functions mein nahi hota. Rest real array hai aur har function type mein chalta hai. Isliye rest prefer karo.

16Spread Operator

What: ... jo iterable/object ko elements mein phaila deta hai. (Rest = collect, Spread = expand.)

// Array
const a = [1, 2], b = [3, 4];
const merged = [...a, ...b, 5];               // [1,2,3,4,5]
const copy = [...a];                          // shallow copy

// Function call
Math.max(...[3, 9, 1]);                       // 9

// Object (override order matter karta hai)
const defaults = { theme: "light", lang: "en" };
const settings = { ...defaults, theme: "dark" };   // { theme:"dark", lang:"en" }

// React immutable update
setCart(prev => ({ ...prev, items: [...prev.items, newItem] }));

[..."hello"];                                  // ["h","e","l","l","o"]

Important: Shallow copy hai: nested objects abhi bhi share hote hain. Object spread sirf own enumerable properties copy karta hai. null/undefined ko spread karna objects mein safe, arrays mein error.

Generators, Async aur Event Loop 7 sawaal

18Generator Functions in JS

What: function* se bana special function jo beech mein pause (yield) aur resume ho sakta hai. Call karne par code chalta nahi, ek generator object (iterator) milta hai; .next() se step-by-step chalta hai.

function* idGenerator() {
  let id = 1;
  while (true) yield id++;          // infinite, par lazy: sirf maangne par banta hai
}
const gen = idGenerator();
gen.next();   // { value: 1, done: false }
gen.next();   // { value: 2, done: false }

function* demo() {
  const name = yield "naam batao";   // yield value bahar bhejta hai
  console.log("Hello", name);        // next(value) se andar value aati hai
  return "end";
}
const g = demo();
g.next();          // { value: "naam batao", done: false }
g.next("Riya");    // logs "Hello Riya" -> { value: "end", done: true }

Methods: next(v), return(v) (jaldi band), throw(err) (andar error daalna). yield* doosre generator/iterable ko delegate karta hai.

Why / Real use:

  • Lazy sequences: Paginated products ek-ek page.
  • Custom iterables: [Symbol.iterator] generator se likhna easy.
  • Async flow control: async/await se pehle co library; redux-saga aaj bhi generators par based hai.
  • Async generators (async function* + for await) stream/pagination ke liye.
async function* fetchPages(url) {
  let page = 1;
  while (true) {
    const res = await fetch(`${url}?page=${page++}`).then(r => r.json());
    if (!res.items.length) return;
    yield res.items;
  }
}
for await (const items of fetchPages("/api/products")) render(items);
19JavaScript Single Threaded Language kaise hai?

What: JS engine ke paas ek hi Call Stack hai, to ek time par ek hi kaam execute hota hai. Ek thread = ek main execution flow.

Phir async kaise chalta hai? Browser/Node JS engine ke bahar kaam karte hain (Web APIs: timers, network, DOM events - ye alag threads/C++ mein). Kaam complete hone par callback queue mein aata hai aur event loop use call stack khaali hone par daalta hai (Q21).

console.log("A");
setTimeout(() => console.log("B"), 0);   // Web API ko diya
console.log("C");
// A C B

Fayda: Race conditions/locks nahi, mental model simple. Nuksaan: Heavy synchronous loop poore UI ko freeze kar deta hai:

while (Date.now() - start < 5000) {}   // 5 sec tak page click nahi hoga

Solution: Heavy kaam ko chunks mein todo, Web Workers (Q78) mein bhejo, ya backend par. Note: “single-threaded” JS language ke execution ke baare mein hai, poore browser ke baare mein nahi.

20Callbacks: Kyu zaroorat hai?

What: Callback = ek function jo doosre function ko argument mein diya jata hai aur baad mein (jab kaam ho jaye) call hota hai.

Why: JS single-threaded hai; agar network/file/timer ka wait block karta to app freeze ho jati. Callback bolta hai: “kaam hone par ye function chala dena.”

// Synchronous callback
[1, 2, 3].map(n => n * 2);

// Asynchronous callback
setTimeout(() => console.log("2 sec baad"), 2000);

// Error-first callback (Node style)
fs.readFile("data.json", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});

// Custom
function getProduct(id, callback) {
  setTimeout(() => callback({ id, name: "Shoes" }), 500);
}
getProduct(1, product => console.log(product.name));

Problems: Callback hell (Q45), error handling bikhra hua, “inversion of control” (aap kisi aur ke code par bharosa kar rahe ho ki wo callback ek hi baar call karega). Isliye Promises/async-await aaye.

21Event Loop

What: Wo mechanism jo continuously check karta hai: “Call Stack khaali hai? to queue se agla task utha ke stack par daalo.” Isi se single thread par async kaam hota hai.

Players: Call Stack, Web APIs, Microtask queue, Task (callback/macrotask) queue, Event loop.

Har cycle ka order:

  1. Call stack ka synchronous code pura chalao.
  2. Stack khaali → saari microtasks chalao (naye aaye hue bhi) jab tak queue khaali na ho.
  3. (Browser) zaroorat ho to render/paint.
  4. Ek macrotask lo (setTimeout, DOM event, I/O) aur chalao.
  5. Step 2 se repeat.
console.log("1 sync");
setTimeout(() => console.log("5 macrotask"), 0);
Promise.resolve().then(() => console.log("3 microtask"));
queueMicrotask(() => console.log("4 microtask"));
console.log("2 sync");
// 1 sync, 2 sync, 3 microtask, 4 microtask, 5 macrotask

Real case: ShopKart mein “Add to cart” ke baad heavy price calculation sync loop mein tha; button click ka animation atka. Calculation ko setTimeout/worker mein hatane se UI smooth. Takeaway: setTimeout(fn, 0) ka matlab “turant” nahi, “current stack + microtasks ke baad.”

22Callback Queue (Task / Macrotask Queue)

What: Wo queue jahan Web APIs ke completed callbacks wait karte hain: setTimeout, setInterval, DOM events (click), XMLHttpRequest, MessageChannel, I/O. Event loop inhe ek-ek karke, call stack khaali hone par (aur microtasks ke baad) utha ta hai.

Flow:

setTimeout(() => console.log("timeout"), 0);
button.addEventListener("click", () => console.log("click"));
  1. setTimeout Web API ko diya, timer chala.
  2. Timer pura → callback callback queue mein gaya.
  3. Event loop: stack khaali + microtasks khaali → callback stack par.

Notes:

  • Queue FIFO hai; par setTimeout(fn, 0) ki minimum delay browser mein ~1-4ms ho sakti hai (nested timers par 4ms clamp).
  • setTimeout ka delay minimum hota hai, guarantee nahi (stack busy ho to late).
  • Microtask queue ki priority isse zyada hai (Q23).
23Microtask Queue

What: Higher-priority queue jisme jate hain: Promise .then/.catch/.finally callbacks, await ke baad ka code, queueMicrotask, MutationObserver. Node mein process.nextTick alag, usse bhi pehle chalti hai (Q81).

Rule: Jab call stack khaali hota hai, event loop poori microtask queue khaali karta hai (beech mein naye microtasks bhi) uske baad hi next macrotask ya rendering.

setTimeout(() => console.log("macro"), 0);
Promise.resolve().then(() => console.log("micro 1"))
       .then(() => console.log("micro 2"));
console.log("sync");
// sync, micro 1, micro 2, macro

async/await ke saath:

async function f() {
  console.log("A");
  await null;                 // yahan se neeche ka code microtask
  console.log("B");
}
f(); console.log("C");        // A C B

Danger: Microtask baar-baar naya microtask banaye to macrotasks/render bhookhe reh jate hain (starvation) - Q34.

24Promises

What: Ek object jo future mein aane wali value (ya error) ko represent karta hai. 3 states: pending → fulfilled / rejected (ek baar settle hua to badalta nahi).

const getStock = id => new Promise((resolve, reject) => {
  setTimeout(() => (id > 0 ? resolve({ id, stock: 12 }) : reject(new Error("Invalid id"))), 300);
});

What: Function ko fixed time interval mein maximum ek baar chalne dena, chahe event kitni bhi baar fire ho.

function throttle(fn, limit) {
  let lastCall = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      return fn.apply(this, args);
    }
  };
}

33JavaScript code ko parse aur compile kaise karta hai? (Step by step)

  2. Scanner / Tokenizer (Lexical analysis): Code ko tokens mein todta hai: const, x, =, 5.

  8. Execution Context + Call Stack: Global context banta hai (creation phase: hoisting, this; execution phase: line by line, Q49).
  9. Memory management: Heap allocation + Garbage Collection (Q51).

38mapLimit

What: Array ke har item par async function chalana, par ek time par maximum limit tasks parallel, aur results order mein wapas. map + concurrency control.

Why: 500 images upload / 1000 API calls ek saath fire karoge to server 429 Too Many Requests dega ya browser connection limit (6/host) aur memory pe pressure. Sequential karoge to bahut slow. Beech ka rasta: limit.

Callback style (async library jaisa, classic interview version):

function mapLimit(arr, limit, iteratee, done) {
  const results = new Array(arr.length);
  let started = 0, finished = 0, failed = false;
  if (!arr.length) return done(null, results);

  function next() {
    if (failed || started >= arr.length) return;
    const i = started++;
    iteratee(arr[i], (err, val) => {
      if (failed) return;
      if (err) { failed = true; return done(err); }
      results[i] = val;
      if (++finished === arr.length) return done(null, results);
      next();                                   // ek khatam, agla start
    });
  }
  for (let k = 0; k < Math.min(limit, arr.length); k++) next();
}

// Use
const uploadOne = (file, cb) => setTimeout(() => cb(null, file.name + " done"), 300);

Idea: Pehle limit tasks start karo; jab ek khatam ho, naya start. Promise/async version P4 mein. Real use: ShopKart admin mein 200 product images bulk upload, 5 ek saath.

    target[key] = v && typeof v === "object" && !Array.isArray(v) ? safeMerge(target[key] ?? {}, v) : v;
  }
  return target;
}

Function.prototype.myCall = function (context, ...args) {

Part 1: Promise class from scratch (simplified A+ spec).

class MyPromise {
  #state = "pending";
  #value;
  #handlers = [];

  constructor(executor) {
    let called = false;
    const resolve = v => { if (called) return; called = true; this.#resolveWith(v); };
    const reject = e => { if (called) return; called = true; this.#settle("rejected", e); };
    try { executor(resolve, reject); } catch (e) { reject(e); }
  }

  #resolveWith(v) {
    if (v === this) return this.#settle("rejected", new TypeError("Chaining cycle"));
    if (v && (typeof v === "object" || typeof v === "function")) {
      let then;
      try { then = v.then; } catch (e) { return this.#settle("rejected", e); }
      if (typeof then === "function") {              // thenable/promise ko follow karo
        let done = false;
        try {
          then.call(v,
            y => { if (!done) { done = true; this.#resolveWith(y); } },
            r => { if (!done) { done = true; this.#settle("rejected", r); } });
        } catch (e) { if (!done) { done = true; this.#settle("rejected", e); } }
        return;
      }
    }
    this.#settle("fulfilled", v);
  }

  #settle(state, value) {
    if (this.#state !== "pending") return;
    this.#state = state; this.#value = value;
    this.#flush();
  }

  #flush() {
    if (this.#state === "pending") return;
    const hs = this.#handlers; this.#handlers = [];
    hs.forEach(h => queueMicrotask(h));              // callbacks hamesha async (microtask)
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      this.#handlers.push(() => {
        const cb = this.#state === "fulfilled" ? onFulfilled : onRejected;
        if (typeof cb !== "function") {              // pass-through
          return this.#state === "fulfilled" ? resolve(this.#value) : reject(this.#value);
        }
        try { resolve(cb(this.#value)); } catch (e) { reject(e); }
      });
      this.#flush();
    });
  }

  catch(onRejected) { return this.then(undefined, onRejected); }

  finally(cb) {
    return this.then(
      v => MyPromise.resolve(cb()).then(() => v),
      e => MyPromise.resolve(cb()).then(() => { throw e; })
    );
  }

  static resolve(v) { return v instanceof MyPromise ? v : new MyPromise(res => res(v)); }
  static reject(e) { return new MyPromise((_, rej) => rej(e)); }
}

function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const items = Array.from(iterable);
    if (items.length === 0) return resolve([]);
    const results = new Array(items.length);
    let pending = items.length;
    items.forEach((item, i) => {
      Promise.resolve(item).then(v => {
        results[i] = v;                              // order preserve (index se)
        if (--pending === 0) resolve(results);
      }, reject);                                    // pehla reject = poora reject
    });
  });
}

function promiseAllSettled(iterable) {
  return promiseAll(Array.from(iterable, p =>

      reason => ({ status: "rejected", reason })
    )));
}

function promiseRace(iterable) {
  return new Promise((resolve, reject) => {
    for (const p of iterable) Promise.resolve(p).then(resolve, reject);   // pehla settle

}

function promiseAny(iterable) {
  return new Promise((resolve, reject) => {
    const items = Array.from(iterable);

    });
  });
}

    lastArgs = lastThis = undefined;
    result = fn.apply(ctx, args);
    return result;
  }

  function debounced(...args) {
    lastArgs = args; lastThis = this;
    const callNow = leading && !timer;               // pehli call turant
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (trailing && lastArgs) invoke();            // last call delay ke baad
    }, wait);
    if (callNow) invoke();
    return result;
  }

  debounced.cancel = () => { clearTimeout(timer); timer = null; lastArgs = lastThis = undefined; };
  debounced.flush = () => {
    if (timer) { clearTimeout(timer); timer = null; if (lastArgs) return invoke(); }
    return result;
  };
  return debounced;
}

P6Throttle polyfill (leading, trailing, cancel)
function throttle(fn, wait, { leading = true, trailing = true } = {}) {
  let timer = null, lastArgs, lastThis, lastCall = 0;

  function run(time) {
    lastCall = time;
    const args = lastArgs, ctx = lastThis;
    lastArgs = lastThis = undefined;
    fn.apply(ctx, args);
  }

  function throttled(...args) {
    const now = Date.now();
    if (!lastCall && !leading) lastCall = now;
    const remaining = wait - (now - lastCall);
    lastArgs = args; lastThis = this;

    if (remaining <= 0 || remaining > wait) {        // window khul chuki hai
      if (timer) { clearTimeout(timer); timer = null; }
      run(now);
    } else if (!timer && trailing) {                 // window ke andar: last call ko baad mein chalao
      timer = setTimeout(() => {
        timer = null;
        if (lastArgs) run(leading ? Date.now() : 0);
      }, remaining);
    }
  }

  throttled.cancel = () => { clearTimeout(timer); timer = null; lastArgs = lastThis = undefined; lastCall = 0; };
  return throttled;
}

P7Event Emitter

What: Pub/Sub pattern: on (subscribe), off (unsubscribe), once, emit (publish). Node ka EventEmitter, browser ka EventTarget, Redux/Vue ka event bus isi idea par.

class EventEmitter {
  #events = new Map();

  on(name, listener) {
    if (!this.#events.has(name)) this.#events.set(name, []);
    this.#events.get(name).push(listener);
    return () => this.off(name, listener);           // unsubscribe function
  }

  off(name, listener) {
    const list = this.#events.get(name);
    if (!list) return this;
    const filtered = list.filter(l => l !== listener && l.original !== listener);
    filtered.length ? this.#events.set(name, filtered) : this.#events.delete(name);
    return this;
  }

  once(name, listener) {
    const wrapper = (...args) => { this.off(name, wrapper); listener(...args); };
    wrapper.original = listener;                     // off(original) bhi chale
    return this.on(name, wrapper);
  }

  emit(name, ...args) {
    const list = this.#events.get(name);
    if (!list) return false;
    [...list].forEach(l => l(...args));              // copy par iterate: beech mein off safe
    return true;
  }

  listenerCount(name) { return this.#events.get(name)?.length ?? 0; }
}

async function parallelLimit(tasks, limit) {
  const results = new Array(tasks.length);
  let index = 0, active = 0;

  return new Promise((resolve, reject) => {
    if (tasks.length === 0) return resolve(results);
    let completed = 0;

    function launch() {
      while (active < limit && index < tasks.length) {
        const i = index++;
        active++;
        tasks[i]().then(res => {
          results[i] = res;
          active--; completed++;
          if (completed === tasks.length) resolve(results);
          else launch();                              // jagah khaali, agla task
        }).catch(reject);
      }
    }
    launch();
  });
}

function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== "object") return value;     // primitives & functions
  if (seen.has(value)) return seen.get(value);                       // circular reference

  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);

  if (value instanceof Map) {
    const m = new Map(); seen.set(value, m);
    value.forEach((v, k) => m.set(deepClone(k, seen), deepClone(v, seen)));
    return m;
  }
  if (value instanceof Set) {
    const s = new Set(); seen.set(value, s);
    value.forEach(v => s.add(deepClone(v, seen)));
    return s;
  }

  const copy = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, copy);
  for (const key of Reflect.ownKeys(value)) {                        // symbol keys bhi
    copy[key] = deepClone(value[key], seen);
  }
  return copy;
}

// 1. Custom key resolver + this support
function memoize(fn, resolver = (...args) => JSON.stringify(args)) {
  const cache = new Map();
  const memoized = function (...args) {
    const key = resolver(...args);
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
  memoized.cache = cache;
  memoized.clear = () => cache.clear();
  return memoized;
}

// 2. LRU Cache (Least Recently Used) - Map ki insertion order ka use
class LRUCache {
  constructor(capacity) { this.capacity = capacity; this.map = new Map(); }
  get(key) {
    if (!this.map.has(key)) return undefined;
    const val = this.map.get(key);
    this.map.delete(key); this.map.set(key, val);      // recent bana do (end mein)
    return val;
  }
  set(key, val) {
    if (this.map.has(key)) this.map.delete(key);
    else if (this.map.size >= this.capacity) this.map.delete(this.map.keys().next().value); // sabse purana hatao
    this.map.set(key, val);
  }
}

// 3. TTL + async (promise ko cache karo taaki duplicate in-flight calls na hon)
function memoizeAsync(fn, ttl = 60_000) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    const hit = cache.get(key);
    if (hit && Date.now() - hit.time < ttl) return hit.promise;
    const promise = fn.apply(this, args).catch(err => { cache.delete(key); throw err; }); // fail cache na ho
    cache.set(key, { promise, time: Date.now() });
    return promise;
  };
}

Problem: Network/API fail ho sakti hai (flaky). Fail hone par N baar dobara try karo, beech mein delay (exponential backoff + jitter) ke saath.

async function retry(fn, { retries = 3, delay = 500, factor = 2, jitter = true,
                           shouldRetry = () => true, onRetry } = {}) {
  let attempt = 0, wait = delay;
  while (true) {
    try {
      return await fn(attempt);
    } catch (err) {
      attempt++;
      if (attempt > retries || !shouldRetry(err)) throw err;      // limit ya retry-able nahi
      onRetry?.(err, attempt);
      const sleepFor = jitter ? wait * (0.5 + Math.random() / 2) : wait;
      await sleep(sleepFor);
      wait *= factor;                                             // 500, 1000, 2000...
    }
  }
}

Proxy: Kisi object ke operations (get, set, delete, has, function call…) ko intercept karne wala wrapper. Reflect: Wahi default operations ko methods ke roop mein deta hai (proxy ke andar default behaviour call karne ke liye).
