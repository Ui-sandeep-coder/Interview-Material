Node.js Core 12 sawaal

1Node.js kya hai? Iska architecture kaisa hai?

What: Node.js ek JavaScript runtime hai jo browser ke bahar (server par) JS chalata hai. Ye language nahi, runtime hai: Chrome ka V8 engine + libuv (async I/O library) + C++ bindings + built-in modules (fs, http, crypto…).

Architecture:

Aapka JS code
   |
Node.js APIs (fs, http, crypto, stream...)
   |
C++ bindings
   |-- V8   : JS ko machine code mein chalata hai
   |-- libuv: event loop + thread pool + OS async I/O (epoll/kqueue/IOCP)

Why Node: I/O-heavy kaam (APIs, chat, streaming, proxies) ke liye best, kyunki ek hi thread hazaaron connections sambhal leta hai (non-blocking). Frontend aur backend dono mein ek hi language (TypeScript), code/type sharing.

Kab nahi: CPU-heavy kaam (video encode, ML, bade calculations) main thread ko block karte hain; wahan worker threads / alag service (Go, Java, Python) ya queue.

import http from "node:http";
http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ ok: true }));
}).listen(3000);

ShopKart: API gateway, orders/catalog REST APIs Node mein (I/O bound: DB + cache calls), image resizing worker threads/Lambda mein.

2Node.js Event Loop ke phases aur libuv Thread Pool

(JS ka basic event loop JS guide mein hai; yahan Node-specific.)

Phases (ek loop iteration):

  1. timers: setTimeout/setInterval ke callbacks.
  2. pending callbacks: Kuch system-level callbacks.
  3. idle/prepare: Internal.
  4. poll: Naye I/O events lena aur unke callbacks chalana (yahan loop zaroorat par wait karta hai).
  5. check: setImmediate callbacks.
  6. close callbacks: socket.on("close") jaise.

Har phase ke baad (aur callbacks ke beech) process.nextTick queue phir Promise microtasks drain hote hain.

libuv Thread Pool (default 4 threads, UV_THREADPOOL_SIZE se 128 tak): In kaamon ke liye use hota hai: fs (most), dns.lookup, crypto (pbkdf2, scrypt, randomBytes), zlib. Network I/O (sockets) thread pool use nahi karta, OS ke epoll/kqueue se chalta hai.

const crypto = require("crypto");
for (let i = 0; i < 8; i++) {
  crypto.pbkdf2("pwd", "salt", 1e6, 64, "sha512", () => console.log(i, Date.now() - start));
}
// 4 pehle, phir 4 baad mein (pool size 4)

Real insight: Bahut saare parallel bcrypt/fs calls pool bhar dete hain aur baaki fs bhi queue mein ruk jata hai. Login spike par pool size badhao ya argon2 workers use karo.

4Blocking vs Non-blocking I/O

Blocking: Operation complete hone tak thread ruka rehta hai (fs.readFileSync). Poore server ke saare requests ruk jate hain. Non-blocking: Request OS/libuv ko do, thread aage badhta hai, kaam hone par callback/promise.

// Blocking (server mein NA karein)
const data = fs.readFileSync("big.json");     // 200ms tak koi doosri request nahi chalegi

// Non-blocking
const data = await fs.promises.readFile("big.json");

// CPU blocking jo dikhta nahi
app.get("/report", (req, res) => {
  const out = hugeArray.sort().map(heavy);     // main thread block
  res.json(out);
});

Kaun se kaam block karte hain (watch karo): *Sync functions, bade JSON.parse/stringify, regex catastrophic backtracking, crypto.pbkdf2Sync, bade loops, bade array sort.

Fix: Async APIs, streams, worker threads, kaam ko chunks mein (setImmediate), ya queue + worker service. Detect: Event loop lag (perf_hooks.monitorEventLoopDelay), clinic doctor.

7Streams aur Buffers

Buffer: Raw binary data ka fixed chunk (memory mein bytes). Stream: Data ko chhote chunks mein process karna, poora memory mein load kiye bina.

4 types: Readable, Writable, Duplex (dono), Transform (beech mein badalna, jaise gzip).

// 2GB file ko memory mein load karna (BAD)
const all = await fs.promises.readFile("big.csv");

// Stream (GOOD): constant memory
import { pipeline } from "node:stream/promises";
import zlib from "node:zlib";
await pipeline(
  fs.createReadStream("big.csv"),
  zlib.createGzip(),
  fs.createWriteStream("big.csv.gz")
);

// HTTP response ko stream karna
app.get("/export", (req, res) => {
  res.setHeader("Content-Type", "text/csv");
  pipeline(db.queryStream("select * from orders"), toCsvTransform(), res, err => err && console.error(err));
});

Backpressure: Jab writer dheema ho to reader ko rokna (write() false return kare to drain ka wait). pipeline ye khud sambhalta hai aur errors par sab streams destroy karta hai (.pipe() nahi). Use: File upload/download, CSV export, video streaming, S3 se proxy, log processing.

8EventEmitter aur Graceful Shutdown

EventEmitter: Node ka pub/sub base (http.Server, streams sab isse bane hain).

import { EventEmitter } from "node:events";
const bus = new EventEmitter();
bus.on("order:placed", order => sendEmail(order));
bus.once("ready", () => console.log("ek baar"));
bus.emit("order:placed", { id: 1 });

Dhyan: error event ka listener na ho to process crash. Default max 10 listeners (leak warning). Listeners sync chalte hain.

Graceful shutdown (deployment/scale-down par zaroori):

const server = app.listen(3000);

async function shutdown(signal: string) {
  console.log(signal, "mila: naye connections band");
  server.close(async () => {                    // in-flight requests khatam hone do
    await db.end();                             // DB pool band
    await redis.quit();
    process.exit(0);
  });
  setTimeout(() => process.exit(1), 10_000).unref();   // force exit safety
}
process.on("SIGTERM", () => shutdown("SIGTERM"));     // Docker/K8s/ECS ye bhejte hain
process.on("SIGINT", () => shutdown("SIGINT"));

Why: Bina iske rolling deployment mein chal rahe payments/requests beech mein kat jate hain. Kubernetes mein readiness probe fail karke traffic roko, phir shutdown.

Do tarah ke errors:

  • Operational errors: Expected runtime problems (DB down, validation fail, 404, timeout). Handle karo, user ko sahi response.
  • Programmer errors: Bug (undefined.x, galat argument). Fix karo; process ko crash hone do (restart manager sambhale).
export class AppError extends Error {
  constructor(public statusCode: number, message: string, public code = "APP_ERROR", public isOperational = true) {
    super(message);
    Error.captureStackTrace(this, this.constructor);
  }
}
throw new AppError(404, "Product nahi mila", "PRODUCT_NOT_FOUND");

Global safety nets:

process.on("unhandledRejection", reason => { logger.error({ reason }, "unhandledRejection"); throw reason; });
process.on("uncaughtException", err => {
  logger.fatal({ err }, "uncaughtException");
  shutdown("uncaughtException");               // state corrupt ho sakti hai: log + graceful exit, PM2/K8s restart

Best practices: Async mein try/catch ya .catch, error ko ek centralized error middleware (Q16) mein bhejna, Error.cause, structured logging (pino), kabhi bhi error ko silently nigalna nahi, user ko stack trace nahi dikhana, error codes consistent.

11Node.js application ki performance kaise badhate ho?

Checklist (pehle measure, phir fix):

  1. Event loop block mat karo: Sync APIs, heavy CPU → worker threads/queue.
  2. DB optimize: Index, N+1 hatao, select sirf zaroori columns, connection pool, pagination.
  3. Caching: Redis (hot data), HTTP cache headers, in-memory LRU, CDN.
  4. Parallelize independent calls: Promise.all.
  5. Compression: gzip/brotli (reverse proxy par), payload chhota (fields filter).
  6. Scale: Cluster/PM2/containers, load balancer, stateless services.
  7. Streams badi files/exports ke liye.
  8. Keep-alive HTTP agent, DB/HTTP connection reuse.
  9. Logging: pino (fast), sync console.log heavy loops mein nahi.
  10. Node version/updates, NODE_ENV=production.
  11. Offload: Email, PDF, image kaam queue (SQS/BullMQ) par.

Tools: autocannon/k6 (load test), clinic.js, 0x flamegraph, node --prof, Chrome DevTools --inspect, APM (Datadog, New Relic), CloudWatch.

Real result (ShopKart): /products API 800ms → 90ms: index on category, Redis cache (60s), N+1 remove (include), Promise.all for price + stock.

12Node.js mein Memory Leaks kaise dhundhte aur fix karte ho?

Symptoms: RSS/heap dheere-dheere badhta hai, GC baar-baar chalta hai, aakhir JavaScript heap out of memory, container OOMKilled (exit code 137).

Common causes: Global arrays/Maps jo badhte rehte hain (unbounded cache), event listeners jo hatayein nahi (MaxListenersExceededWarning), closures mein bade objects, timers/intervals clear nahi, requests ke objects ko global mein pakadna, bade sessions in-memory.

Debug steps:

  1. Confirm: process.memoryUsage() / CloudWatch metrics trend.
  2. Run with inspector: node --inspect server.js → Chrome chrome://inspect → Memory tab → Heap snapshots (load se pehle aur baad, Comparison view mein kaun badh raha hai).
  3. Heap profiling in production: heapdump/v8.writeHeapSnapshot(), Clinic.js heapprofiler.
  4. Retainers dekho: Kaun sa reference object ko zinda rakh raha hai.
  5. Fix + verify load test se.
// Leak: har request par listener jama
app.get("/x", (req, res) => { bus.on("tick", () => res.write("t")); });   // kabhi remove nahi

// Fix
app.get("/x", (req, res) => {
  const h = () => res.write("t");
  bus.on("tick", h);
  req.on("close", () => bus.off("tick", h));
});

// Unbounded cache -> LRU (max size)

Temporary guard: --max-old-space-size, container memory limits + restart, par root cause fix karo.

13Express.js kya hai? Request-Response lifecycle

What: Node ke upar ek minimal web framework: routing + middleware chain. Node ke raw http module ka comfortable wrapper.

import express from "express";
const app = express();

app.use(express.json());                              // body parser middleware

app.get("/api/products/:id", async (req, res) => {
  const product = await productService.getById(req.params.id);
  res.status(200).json(product);
});

app.listen(3000, () => console.log("up"));

Lifecycle:

Client -> [Global middlewares: logger, cors, helmet, json parser]
       -> [Route match: method + path]
       -> [Route middlewares: auth, validate]
       -> [Controller handler -> service -> DB]
       -> res.json()  (response bheja)
       -> (error ho to) -> [Error-handling middleware]

Key objects: req (params, query, body, headers, cookies), res (status, json, send, redirect, set). Har request ko ek hi response milna chahiye (do baar bhejne par “Cannot set headers after they are sent”).

14Middleware kya hai? Kitne types, order kyun matter karta hai?

What: Function (req, res, next) jo request-response ke beech chalta hai; request modify kar sakta hai, response bhej sakta hai, ya next() se agle ko control de.

const logger: RequestHandler = (req, res, next) => {
  const start = Date.now();
  res.on("finish", () => console.log(req.method, req.originalUrl, res.statusCode, Date.now() - start, "ms"));
  next();
};
app.use(logger);                      // application-level
app.use("/admin", authenticate, authorize("admin"), adminRouter);   // path + route-level

Types: Application-level (app.use), Router-level, Built-in (express.json, static), Third-party (cors, helmet, morgan), Error-handling (4 args), route-specific.

Order matter karta hai: Upar se neeche chalte hain.

app.use(helmet());
app.use(cors({ origin: config.CLIENT_URL, credentials: true }));
app.use(express.json({ limit: "1mb" }));
app.use(requestId, logger);
app.use("/api", apiRouter);           // routes
app.use(notFound);                    // 404
app.use(errorHandler);                // sabse aakhir mein

Galtiyan: next() bhool jana (request hang), next() ke baad bhi response bhejna, error middleware route se pehle likhna, body parser se pehle req.body padhna.

19Request Validation (Zod / Joi)

Why: Client par kabhi bharosa nahi. Galat/malicious input DB tak pahunchne se pehle rok do.

import { z } from "zod";

export const createProductSchema = z.object({
  body: z.object({
    name: z.string().min(2).max(120),
    price: z.number().positive(),
    category: z.enum(["shoes", "bags", "watches"]),
    tags: z.array(z.string()).max(10).default([]),
  }),
});
export type CreateProductInput = z.infer<typeof createProductSchema>["body"];

export const validate = (schema: z.ZodTypeAny): RequestHandler => (req, res, next) => {
  const result = schema.safeParse({ body: req.body, query: req.query, params: req.params });
  if (!result.success) {
    return res.status(400).json({ error: { code: "VALIDATION", details: result.error.flatten() } });
  }
  Object.assign(req, result.data);      // typed + cleaned data
  next();
};

router.post("/", validate(createProductSchema), createProduct);

20Express mein JWT Authentication + Authorization (RBAC): full flow
// auth.service.ts
const ACCESS_TTL = "15m", REFRESH_TTL_DAYS = 7;

export async function login(email: string, password: string) {
  const user = await userRepo.findByEmail(email);
  const ok = user && (await bcrypt.compare(password, user.passwordHash));
  if (!ok) throw new AppError(401, "Email ya password galat", "INVALID_CREDENTIALS");  // dono ke liye same msg

  const accessToken = jwt.sign({ sub: user.id, role: user.role }, config.JWT_SECRET, { expiresIn: ACCESS_TTL });
  const refreshToken = crypto.randomBytes(48).toString("hex");
  await refreshRepo.save({ userId: user.id, tokenHash: sha256(refreshToken), expiresAt: addDays(REFRESH_TTL_DAYS) });
  return { accessToken, refreshToken, user: publicUser(user) };
}

// controller: refresh token httpOnly cookie mein
res.cookie("rt", refreshToken, { httpOnly: true, secure: true, sameSite: "strict", maxAge: 7 * 864e5, path: "/api/auth" });
res.json({ accessToken });

// middleware
export const authenticate: RequestHandler = (req, res, next) => {
  const token = req.headers.authorization?.split(" ")[1];
  if (!token) return next(new AppError(401, "Token missing"));
  try {
    const payload = jwt.verify(token, config.JWT_SECRET) as { sub: string; role: Role };
    req.user = { id: payload.sub, role: payload.role };
    next();
  } catch { next(new AppError(401, "Token invalid ya expire")); }
};

export const authorize = (...roles: Role[]): RequestHandler => (req, res, next) =>

31Idempotency Key: payment dobara na kate

Problem: User ne “Pay” dabaya, network timeout aaya, client ne retry kiya. Bina protection ke do baar payment.

Solution: Client har logical operation ke liye unique Idempotency-Key (UUID) bhejta hai; server pehli baar kaam karke result store karta hai, same key aane par wahi result dobara deta hai.

router.post("/payments", authenticate, async (req, res) => {
  const key = req.header("Idempotency-Key");
  if (!key) return res.status(400).json({ error: { code: "KEY_REQUIRED" } });

  const cacheKey = `idem:${req.user!.id}:${key}`;
  const claimed = await redis.set(cacheKey, "IN_PROGRESS", { NX: true, EX: 86400 });   // atomic claim
  if (!claimed) {
    const saved = await redis.get(cacheKey);
    if (saved === "IN_PROGRESS") return res.status(409).json({ error: { code: "IN_PROGRESS" } });
    const { status, body } = JSON.parse(saved!);
    return res.status(status).json(body);                     // purana result
  }

  try {
    const payment = await paymentService.charge(req.user!.id, req.body);
    const body = { id: payment.id, status: payment.status };
    await redis.set(cacheKey, JSON.stringify({ status: 201, body }), { EX: 86400 });
    res.status(201).json(body);
  } catch (e) { await redis.del(cacheKey); throw e; }
});

DB level safety: orders.idempotency_key par UNIQUE constraint (race mein bhi duplicate nahi). Stripe/Razorpay isi pattern se chalte hain. Retries (Q71) safe tab hi jab operation idempotent ho.

ACID:

  • Atomicity: Sab ya kuch nahi (payment kata + order nahi bana = rollback).
  • Consistency: Transaction constraints ke andar valid state se valid state mein le jata hai.
  • Isolation: Parallel transactions ek dusre ko disturb na karein.
  • Durability: Commit ke baad data crash mein bhi bacha rahe (WAL).

45Indexes: kaise kaam karte hain, kab lagayein

What: Table ke column(s) par bani alag sorted structure (mostly B-tree) jisse search O(n) full table scan ki jagah O(log n) mein ho.

CREATE INDEX idx_products_category ON products(category);
CREATE UNIQUE INDEX idx_users_email ON users(email);
CREATE INDEX idx_orders_user_created ON orders(user_id, created_at DESC);   -- composite

Composite index rule (leftmost prefix): (user_id, created_at) index WHERE user_id = ? aur WHERE user_id = ? AND created_at > ? dono mein kaam aata hai, par sirf WHERE created_at > ? mein nahi. Order: Equality columns pehle, range/sort baad mein.

Kab lagao: WHERE, JOIN (foreign keys), ORDER BY, GROUP BY wale columns, high selectivity (kam duplicate) wale.

Kab nahi / costs: Har index write (INSERT/UPDATE/DELETE) slow karta hai aur storage leta hai. Chhoti tables, low-cardinality column (gender, isActive), jo columns kam query hote hain.

Index kab use nahi hota: WHERE LOWER(email) = ... (function lagi), LIKE '%abc' (leading wildcard), type mismatch, OR kuch cases mein, bahut kam selective filter.

Types: B-tree (default), Hash, GIN (JSONB/full-text/arrays), Partial index (WHERE deleted_at IS NULL), Covering index (INCLUDE), Unique. Clustered vs non-clustered: MySQL InnoDB mein primary key clustered hoti hai (data usi order mein). Verify hamesha EXPLAIN se (Q49).

47Normalization vs Denormalization

Normalization: Data ko tables mein todna taaki duplicate na ho aur anomalies na aayein.

  • 1NF: Har cell atomic (ek value), repeating groups nahi.
  • 2NF: 1NF + partial dependency nahi (non-key column poori primary key par depend).
  • 3NF: 2NF + transitive dependency nahi (non-key column sirf key par depend, kisi aur non-key par nahi).
Galat: orders(id, user_id, user_name, user_city, product_name, ...)   -> user_name duplicate, update anomaly
Sahi:  users(id, name, city)  orders(id, user_id)  order_items(order_id, product_id, qty)  products(id, name, price)

Fayde: Kam storage, consistent updates. Nuksaan: Zyada joins (read slow).

Denormalization: Jaan-bujhkar duplicate/precomputed data rakhna read speed ke liye (e.g. orders.total, products.review_count, order mein product ka price snapshot).

Rule: Default normalize (3NF), measure karke jahan read bottleneck ho wahan denormalize, aur duplicate data ko consistent rakhne ka plan (triggers/events/jobs). Price snapshot zaroor rakho: product ka price baad mein badle to purane orders na badlein.

50Connection Pooling

Problem: Har request par naya DB connection banana slow (TCP + TLS + auth) aur DB ke connections limited (Postgres default ~100). Zyada connections = memory/CPU waste.

  connectionString: config.DATABASE_URL,
  max: 20,                       // pool size
  idleTimeoutMillis: 30_000,
  connectionTimeoutMillis: 2_000,
});

54Optimistic vs Pessimistic Locking (Inventory oversell problem)

55Replication, Sharding aur Partitioning
  • Replication: Data ki copies. Primary (writes) + Read replicas (reads). Read scale + high availability (failover). Replication lag → replica se purana data (read-your-writes ke liye critical read primary se).
  • Partitioning: Ek badi table ko ek hi server par chhote parts mein (date/hash/range) todna → query/maintenance fast.
  • Sharding: Data ko alag servers par baantna (horizontal scale). Shard key important.
Sharding: user_id % 4 -> shard0..shard3

Shard key choice: High cardinality, even distribution (hot shard na bane), query mein aksar use ho. Bura key: country (ek country bohot bada), created_at (naya data ek hi shard par).

Problems: Cross-shard joins/transactions, resharding, hot spots. Isliye pehle vertical scale + indexes + cache + read replicas; sharding last resort. Consistent hashing (A1) resharding kam painful banata hai. Managed: Aurora (replicas), DynamoDB/Cosmos (auto partition), Mongo sharded cluster.

56CAP Theorem aur Consistency Models

CAP: Distributed system mein network partition (P) hone par aapko Consistency (C) ya Availability (A) mein se ek chunna padta hai (dono nahi). Partition real life mein hota hi hai, to practical choice: CP ya AP.

  • CP: Consistency pehle; partition mein kuch requests reject (banking, inventory) - e.g. HBase, Mongo (default primary reads), Zookeeper.
  • AP: Availability pehle; purana data de sakta hai, baad mein sync (eventual consistency) - e.g. Cassandra, DynamoDB (eventual), DNS.

Consistency models: Strong (read hamesha latest), Eventual (kuch der mein sab replicas same), Read-your-writes, Causal.

BASE (NoSQL ka approach): Basically Available, Soft state, Eventually consistent, ACID ke muqable mein.

Real: Cart/likes/view counts → eventual theek. Payments/stock → strong. DynamoDB mein ConsistentRead: true option (zyada cost). PACELC: Partition nahi hai tab bhi Latency vs Consistency trade-off.

71Resilience Patterns: Timeout, Retry, Circuit Breaker, Bulkhead

Distributed system mein downstream services fail hoti hain. Agar aapka code blindly wait kare to cascading failure.

  1. Timeout: Har outbound call par (HTTP, DB) timeout. Bina timeout ke request hamesha latak jati hai.
  2. Retry with exponential backoff + jitter: Sirf idempotent/transient errors par (JS guide ka retry polyfill). Retry storm se bacho (max attempts).
  3. Circuit Breaker: Downstream bar-bar fail ho to kuch der call band (fast-fail), phir test.
CLOSED (normal) --failures > threshold--> OPEN (turant error, call nahi) --timeout--> HALF-OPEN (kuch test calls)
     ^------------------------ success ------------------------------------------------|

import CircuitBreaker from "opossum";
const breaker = new CircuitBreaker(callPaymentApi, { timeout: 3000, errorThresholdPercentage: 50, resetTimeout: 10_000 });
breaker.fallback(() => ({ status: "PENDING", note: "Baad mein retry hoga" }));
const result = await breaker.fire(payload);
  1. Bulkhead: Resources alag-alag (alag pool/queue) taaki ek dependency sab consume na kare.
  2. Fallback / graceful degradation: Recommendation service down ho to default products dikhao, checkout na rukne do.
  3. Rate limiting & load shedding: Overload mein kuch requests reject.
  4. Health checks, idempotency (Q31).

ShopKart: Payment gateway slow → 3s timeout + circuit breaker; order “PENDING” mark karke queue se baad mein confirm.

72Distributed Transactions: Saga aur Outbox Pattern

Problem: Microservices mein Order, Payment, Inventory ka alag-alag DB. Ek ACID transaction sab par nahi chal sakti (2PC bhari/fragile).

Saga: Local transactions ki chain; fail hone par compensating actions (undo).

Order Service: create order (PENDING)
  -> Payment: charge          (fail?) -> Order: CANCELLED
  -> Inventory: reserve       (fail?) -> Payment: REFUND -> Order: CANCELLED
  -> Order: CONFIRMED
  • Choreography: Services events se ek dusre ko trigger karti hain (decentralized, simple, trace mushkil).
  • Orchestration: Ek orchestrator steps control karta hai (AWS Step Functions, Temporal) - clear flow, centralized.

Outbox pattern (dual-write problem): “DB mein save + message publish” atomic nahi (DB save hua par publish fail). Fix: Same DB transaction mein outbox table mein event likho, alag relay process use queue par bhejta hai.

BEGIN;
INSERT INTO orders (...);
INSERT INTO outbox (event_type, payload) VALUES ('OrderPlaced', '{...}');
COMMIT;      -- relay worker outbox padhke SQS/Kafka par publish karta hai

Rules: Consumers idempotent, eventual consistency accept, compensations design karo, state machine (order status) clear rakho.

89Lambda Cold Start, Concurrency aur Limits

Cold start: Naye execution environment ka banna: container start → runtime init → aapka init code (imports, clients) → handler. Pehli (ya idle ke baad ki) request slow (Node: ~100-500ms typically; Java/.NET zyada, VPC/bade packages se badhta hai). Warm invocation: Purana environment reuse → fast.

Kam karne ke tareeke:

  • Chhota bundle (esbuild, bina unused deps), lazy import (bhari library sirf zaroorat par).
  • Provisioned Concurrency (pehle se garam instances; paid).
  • SnapStart (Java), ARM64 (Graviton, sasta/fast), zyada memory (CPU badhta).
  • Init mein heavy kaam nahi; SDK v3 modular.
  • Latency-critical path par Lambda ki jagah container (Fargate/ECS) consider karo.

Concurrency:

  • Concurrent executions = ek waqt par chal rahe instances. Har concurrent request = alag environment.
  • Account limit (default 1000/region). Reserved concurrency: Function ke liye guaranteed + upper limit (downstream DB protect karne ke liye cap). Provisioned: Pre-warmed.
  • Limit cross par throttling (429); sync callers ko error, async/SQS retry.

DB connections issue: 1000 concurrent Lambda = 1000 DB connections. Fix: RDS Proxy, reserved concurrency cap, DynamoDB.

Retries: Async invocations 2 retries, SQS trigger visibility timeout + DLQ, stream sources tab tak retry jab tak data expire. Idempotency zaroori.

93DynamoDB: Partition key, Sort key, GSI, Capacity aur Single-table design

Basics: Table mein har item ki Primary key = Partition key (PK) (+ optional Sort key (SK)). PK ka hash decide karta hai item kis partition par. Access pattern ke hisaab se key design karo.

// Item
{ pk: "USER#42", sk: "ORDER#2025-06-01#9001", total: 2999, status: "PAID" }

// Query: user ke saare orders (SK range se)
await ddb.send(new QueryCommand({
  TableName: T, KeyConditionExpression: "pk = :p AND begins_with(sk, :o)",
  ExpressionAttributeValues: { ":p": "USER#42", ":o": "ORDER#" }, ScanIndexForward: false, Limit: 20,
}));

Query vs Scan: Query key se (fast, cheap). Scan poori table (slow/costly, avoid).

Indexes: GSI (Global Secondary Index): alag PK/SK se dusra access pattern (e.g. status + createdAt); eventually consistent. LSI: Same PK, alag SK (table banate waqt hi).

Capacity modes: On-demand (pay per request, spiky) / Provisioned (+ auto scaling, predictable). Hot partition problem: Ek hi PK par zyada traffic → throttling; PK high cardinality chuno.

Other: TTL (auto expire items - sessions), Streams (change events → Lambda), conditional writes (ConditionExpression - optimistic locking/idempotency), Transactions, DAX (cache), item max 400KB, single-table design (alag entity types ek table mein, access patterns ke liye).

await ddb.send(new PutCommand({ TableName: T, Item: item, ConditionExpression: "attribute_not_exists(pk)" }));

D2Two Sum (Hashing pattern)

Problem: Array mein do numbers dhundo jinka sum target ho; unke indices return karo.

Brute force: Do loops, O(n^2). Optimal: Ek pass, Map mein value -> index. Har number ke liye target - num pehle dekha hai kya?

function twoSum(nums, target) {
  const seen = new Map();                         // value -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [];
}
twoSum([2, 7, 11, 15], 9);   // [0, 1]

Complexity: Time O(n), Space O(n). Pattern: “pehle dekha hai kya?” = HashMap/Set (duplicates, pairs, frequency). Variations: Sorted array par two pointers (D4, O(1) space), 3Sum (sort + two pointers O(n^2)), count pairs.

// Valid anagram: O(n) time
function isAnagram(a, b) {
  if (a.length !== b.length) return false;
  const count = new Map();
  for (const c of a) count.set(c, (count.get(c) ?? 0) + 1);
  for (const c of b) {
    if (!count.get(c)) return false;
    count.set(c, count.get(c) - 1);
  }
  return true;
}

// Group anagrams: har word ka canonical key
function groupAnagrams(words) {
  const groups = new Map();
  for (const w of words) {
    const key = [...w].sort().join("");                    // O(k log k)
    // faster key: 26-letter count array -> counts.join("#")
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(w);
  }
  return [...groups.values()];
}

// [["eat","tea","ate"],["tan","nat"],["bat"]]

// 1. Palindrome (alphanumeric, case ignore)
function isPalindrome(s) {
  let l = 0, r = s.length - 1;
  const ok = c => /[a-z0-9]/i.test(c);
  while (l < r) {
    if (!ok(s[l])) { l++; continue; }
    if (!ok(s[r])) { r--; continue; }
    if (s[l].toLowerCase() !== s[r].toLowerCase()) return false;
    l++; r--;
  }
  return true;
}

// 2. Container with most water (heights array)
function maxArea(h) {
  let l = 0, r = h.length - 1, best = 0;
  while (l < r) {
    best = Math.max(best, Math.min(h[l], h[r]) * (r - l));
    h[l] < h[r] ? l++ : r--;                // chhoti diwar aage badhao (badi ko hilane se faayda nahi)
  }
  return best;
}

// 3. 3Sum (sort + two pointers) O(n^2), duplicates skip
function threeSum(nums) {
  nums.sort((a, b) => a - b);
  const res = [];
  for (let i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue;
    let l = i + 1, r = nums.length - 1;
    while (l < r) {
      const sum = nums[i] + nums[l] + nums[r];
      if (sum === 0) {
        res.push([nums[i], nums[l], nums[r]]);
        while (nums[l] === nums[l + 1]) l++;
        while (nums[r] === nums[r - 1]) r--;
        l++; r--;
      } else sum < 0 ? l++ : r--;
    }
  }
  return res;
}

Also: Remove duplicates in-place (slow/fast), move zeroes, merge sorted arrays, linked list cycle (D9). Time O(n) (3Sum O(n^2)), Space O(1).

D5Sliding Window: Longest Substring without Repeating, Max Sum Subarray of size K

Idea: Ek window (contiguous subarray/substring) jo aage badhti hai; har baar naya element add, purana remove, bina dobara compute kiye. Kab: “contiguous subarray/substring”, “longest/shortest with condition”, “size k”.

// Longest substring without repeating chars: O(n)
function lengthOfLongestSubstring(s) {
  const last = new Map();                        // char -> last index
  let start = 0, best = 0;
  for (let i = 0; i < s.length; i++) {
    const c = s[i];
    if (last.has(c) && last.get(c) >= start) start = last.get(c) + 1;   // window shrink
    last.set(c, i);
    best = Math.max(best, i - start + 1);
  }
  return best;
}
lengthOfLongestSubstring("abcabcbb");   // 3

// Max sum of subarray of fixed size k
function maxSumK(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];                // naya add, purana hatao
    best = Math.max(best, sum);
  }
  return best;
}

// Smallest subarray with sum >= target (variable window)
function minSubArrayLen(target, nums) {
  let l = 0, sum = 0, best = Infinity;
  for (let r = 0; r < nums.length; r++) {
    sum += nums[r];
    while (sum >= target) { best = Math.min(best, r - l + 1); sum -= nums[l++]; }
  }
  return best === Infinity ? 0 : best;
}

Complexity: O(n) time (har element max 2 baar), O(1)/O(k) space. Real use: Rate limiting window (A3), moving average, streaming metrics.

function maxSubArray(nums) {

D7Binary Search (aur variations)

Idea: Sorted (ya monotonic) data mein har step search space aadha: O(log n).

function binarySearch(arr, target) {
  let lo = 0, hi = arr.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);   // overflow-safe style
    if (arr[mid] === target) return mid;
    arr[mid] < target ? (lo = mid + 1) : (hi = mid - 1);
  }
  return -1;
}

// Lower bound: pehli position jahan arr[i] >= target (insert position)
function lowerBound(arr, target) {
  let lo = 0, hi = arr.length;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    arr[mid] < target ? (lo = mid + 1) : (hi = mid);
  }
  return lo;
}

// Rotated sorted array mein search
function searchRotated(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (nums[mid] === target) return mid;
    if (nums[lo] <= nums[mid]) {                                   // left half sorted
      target >= nums[lo] && target < nums[mid] ? (hi = mid - 1) : (lo = mid + 1);
    } else {                                                       // right half sorted
      target > nums[mid] && target <= nums[hi] ? (lo = mid + 1) : (hi = mid - 1);
    }
  }
  return -1;
}

“Binary search on answer”: Jab answer monotonic ho (e.g. minimum capacity jisme packages D din mein ship ho jayein) - lo..hi answer range par binary search + feasibility check. Real use: DB indexes (B-tree), git bisect, sorted pagination, first bad version.

function mergeSort(a) {

function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  const r = lo + Math.floor(Math.random() * (hi - lo + 1));        // random pivot: worst case se bachav
  [a[r], a[hi]] = [a[hi], a[r]];

class ListNode { constructor(val, next = null) { this.val = val; this.next = next; } }

// 1. Reverse (iterative) O(n), O(1)
function reverseList(head) {
  let prev = null, cur = head;
  while (cur) {
    const next = cur.next;
    cur.next = prev;           // pointer ulta
    prev = cur; cur = next;
  }
  return prev;
}

// 2. Cycle detection: Floyd's tortoise & hare
function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next; fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}

// 3. Merge two sorted lists (dummy node trick)
function mergeTwoLists(a, b) {
  const dummy = new ListNode(0); let tail = dummy;
  while (a && b) {
    if (a.val <= b.val) { tail.next = a; a = a.next; } else { tail.next = b; b = b.next; }
    tail = tail.next;
  }
  tail.next = a ?? b;
  return dummy.next;
}

// 4. Middle of list (slow/fast), Remove Nth from end (two pointers n gap)
function middle(head) { let s = head, f = head; while (f && f.next) { s = s.next; f = f.next.next; } return s; }

// DFS traversals (recursive)
const inorder = (n, out = []) => (n && (inorder(n.left, out), out.push(n.val), inorder(n.right, out)), out);  // BST mein sorted
const preorder = (n, out = []) => (n && (out.push(n.val), preorder(n.left, out), preorder(n.right, out)), out);

// BFS level order
function levelOrder(root) {
  if (!root) return [];
  const res = [], q = [root];
  while (q.length) {
    const size = q.length, level = [];
    for (let i = 0; i < size; i++) {
      const n = q.shift();
      level.push(n.val);
      n.left && q.push(n.left); n.right && q.push(n.right);
    }
    res.push(level);
  }
  return res;
}

const maxDepth = n => (n ? 1 + Math.max(maxDepth(n.left), maxDepth(n.right)) : 0);

// Validate BST: har node ek (min, max) range mein
function isValidBST(n, lo = -Infinity, hi = Infinity) {
  if (!n) return true;
  if (n.val <= lo || n.val >= hi) return false;
  return isValidBST(n.left, lo, n.val) && isValidBST(n.right, n.val, hi);
}

// BST insert / search: O(h) (balanced: O(log n), skewed: O(n))
function insert(root, v) {
  if (!root) return new TreeNode(v);
  v < root.val ? (root.left = insert(root.left, v)) : (root.right = insert(root.right, v));
  return root;
}

// Lowest Common Ancestor (binary tree)
function lca(root, p, q) {
  if (!root || root === p || root === q) return root;
  const l = lca(root.left, p, q), r = lca(root.right, p, q);
  return l && r ? root : l ?? r;
}

D13Graphs: BFS, DFS, Number of Islands, Topological Sort

Representation: Adjacency list (Map<node, neighbors[]>), sparse graphs ke liye best. Kab: Networks, dependencies, grids, shortest path, connectivity.

const graph = new Map([["A", ["B", "C"]], ["B", ["D"]], ["C", ["D"]], ["D", []]]);

// BFS: level by level, unweighted shortest path
function bfs(start) {
  const seen = new Set([start]), q = [start], order = [];
  for (let i = 0; i < q.length; i++) {              // index se (shift se bachna)
    const n = q[i]; order.push(n);
    for (const nb of graph.get(n) ?? []) if (!seen.has(nb)) { seen.add(nb); q.push(nb); }
  }
  return order;
}
// DFS (recursive)
function dfs(n, seen = new Set(), out = []) {
  seen.add(n); out.push(n);
  for (const nb of graph.get(n) ?? []) if (!seen.has(nb)) dfs(nb, seen, out);
  return out;
}

// Number of Islands (grid DFS)
function numIslands(grid) {
  const R = grid.length, C = grid[0].length; let count = 0;
  const sink = (r, c) => {
    if (r < 0 || c < 0 || r >= R || c >= C || grid[r][c] !== "1") return;
    grid[r][c] = "0";                                   // visited mark
    sink(r + 1, c); sink(r - 1, c); sink(r, c + 1); sink(r, c - 1);
  };
  for (let r = 0; r < R; r++) for (let c = 0; c < C; c++) if (grid[r][c] === "1") { count++; sink(r, c); }
  return count;
}

D14Backtracking: Subsets, Permutations, Combination Sum

Idea: Choices ka tree explore karo: choose → explore → un-choose (backtrack). Constraints se prune. Complexity exponential (n! ya 2^n).

function subsets(nums) {
  const res = [];
  (function go(start, path) {
    res.push([...path]);                       // har path ek valid subset
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);                      // choose
      go(i + 1, path);                         // explore
      path.pop();                              // un-choose
    }
  })(0, []);
  return res;
}

function permutations(nums) {
  const res = [], used = new Array(nums.length).fill(false);
  (function go(path) {
    if (path.length === nums.length) return res.push([...path]);
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true; path.push(nums[i]);
      go(path);
      path.pop(); used[i] = false;
    }
  })([]);
  return res;
}

// Combination sum (numbers reuse allowed)
function combinationSum(cands, target) {
  const res = [];
  (function go(start, path, rem) {
    if (rem === 0) return res.push([...path]);
    for (let i = start; i < cands.length; i++) {
      if (cands[i] > rem) continue;
      path.push(cands[i]); go(i, path, rem - cands[i]); path.pop();
    }
  })(0, [], target);
  return res;
}

DP kab: Overlapping subproblems + optimal substructure. (Brute-force recursion mein same subproblem baar-baar solve ho raha ho.) Approach: (1) State define, (2) Recurrence, (3) Base case, (4) Memoization (top-down) ya Tabulation (bottom-up), (5) Space optimize.

// 1. Climbing stairs (1 ya 2 step): fib jaisa, O(n), O(1) space
function climbStairs(n) {

  return b;

// 2. House robber (adjacent nahi): dp[i] = max(dp[i-1], dp[i-2] + nums[i])
function rob(nums) {
  let prev = 0, cur = 0;
  for (const x of nums) [prev, cur] = [cur, Math.max(cur, prev + x)];
  return cur;
}

// 3. Coin change: minimum coins for amount, O(amount * coins)
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity); dp[0] = 0;
  for (let a = 1; a <= amount; a++)
    for (const c of coins) if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
  return dp[amount] === Infinity ? -1 : dp[amount];
}

// 4. Longest Common Subsequence: O(m*n)
function lcs(a, b) {
  const dp = Array.from({ length: a.length + 1 }, () => new Array(b.length + 1).fill(0));
  for (let i = 1; i <= a.length; i++)
    for (let j = 1; j <= b.length; j++)
      dp[i][j] = a[i - 1] === b[j - 1] ? dp[i - 1][j - 1] + 1 : Math.max(dp[i - 1][j], dp[i][j - 1]);
  return dp[a.length][b.length];
}

// 5. 0/1 Knapsack: weights[], values[], capacity W (1D, reverse loop)
function knapsack(weights, values, W) {
  const dp = new Array(W + 1).fill(0);
  for (let i = 0; i < weights.length; i++)
    for (let w = W; w >= weights[i]; w--) dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
  return dp[W];
}

D16Heap / Priority Queue: Top K Frequent Elements, Kth Largest

Heap: Complete binary tree jahan parent <= children (min-heap). push/pop O(log n), peek O(1). JS mein built-in nahi, khud banao (interview mein bhi).

class MinHeap {
  constructor(cmp = (a, b) => a - b) { this.h = []; this.cmp = cmp; }
  size() { return this.h.length; }
  peek() { return this.h[0]; }
  push(v) {
    const h = this.h; h.push(v); let i = h.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.cmp(h[i], h[p]) >= 0) break;
      [h[i], h[p]] = [h[p], h[i]]; i = p;
    }
  }
  pop() {
    const h = this.h; if (!h.length) return undefined;
    const top = h[0], last = h.pop();
    if (h.length) {
      h[0] = last; let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = l + 1; let s = i;
        if (l < h.length && this.cmp(h[l], h[s]) < 0) s = l;
        if (r < h.length && this.cmp(h[r], h[s]) < 0) s = r;
        if (s === i) break;
        [h[i], h[s]] = [h[s], h[i]]; i = s;
      }
    }
    return top;
  }
}

// Top K frequent: O(n log k)
function topKFrequent(nums, k) {
  const freq = new Map();
  for (const n of nums) freq.set(n, (freq.get(n) ?? 0) + 1);
  const heap = new MinHeap((a, b) => a[1] - b[1]);           // [num, count], chhota count upar
  for (const entry of freq) { heap.push(entry); if (heap.size() > k) heap.pop(); }
  return heap.h.map(([n]) => n);
}
topKFrequent([1, 1, 1, 2, 2, 3], 2);    // [1, 2]

// Kth largest: size-k min-heap, top = answer
function kthLargest(nums, k) {
  const heap = new MinHeap();
  for (const n of nums) { heap.push(n); if (heap.size() > k) heap.pop(); }
  return heap.peek();
}

    })(start, "");
    return out;
  }
}

D22Dijkstra: Shortest Path (Weighted Graph)

Problem: Weighted graph (non-negative weights) mein source se har node tak minimum distance (delivery route, network latency). Idea: Greedy - hamesha abhi tak ka sabse kam distance wala node nikalo (min-heap), uske neighbors relax karo.

// graph: Map<node, [[neighbor, weight], ...]>   (MinHeap D16 se)
function dijkstra(graph, src) {
  const dist = new Map([...graph.keys()].map(n => [n, Infinity]));
  dist.set(src, 0);
  const pq = new MinHeap((a, b) => a[1] - b[1]);          // [node, distance]
  pq.push([src, 0]);

  while (pq.size()) {
    const [u, d] = pq.pop();
    if (d > dist.get(u)) continue;                         // stale entry skip
    for (const [v, w] of graph.get(u) ?? []) {
      const nd = d + w;
      if (nd < dist.get(v)) { dist.set(v, nd); pq.push([v, nd]); }   // relax
    }
  }
  return dist;
}

A1Consistent Hashing

Problem: server = hash(key) % N mein jab server add/remove ho (N badle), lagbhag saari keys ka mapping badal jata hai → cache miss storm / data reshuffle.

Consistent hashing: Servers aur keys dono ko ek hash ring (0..2^32) par rakho; key apne se clockwise agle server par jati hai. Server add/remove par sirf chhota hissa (~1/N) keys move hoti hain. Virtual nodes: Har server ke kai points ring par → even distribution.

function hash(str) {                              // FNV-1a 32-bit
  let h = 2166136261;
  for (let i = 0; i < str.length; i++) { h ^= str.charCodeAt(i); h = Math.imul(h, 16777619); }
  return h >>> 0;
}

class ConsistentHash {
  constructor(nodes = [], vnodes = 100) {
    this.vnodes = vnodes; this.ring = [];             // sorted [{ h, node }]
    nodes.forEach(n => this.addNode(n));
  }
  addNode(node) {
    for (let i = 0; i < this.vnodes; i++) this.ring.push({ h: hash(`${node}#${i}`), node });
    this.ring.sort((a, b) => a.h - b.h);
  }
  removeNode(node) { this.ring = this.ring.filter(e => e.node !== node); }
  getNode(key) {
    if (!this.ring.length) return null;
    const h = hash(key);
    let lo = 0, hi = this.ring.length;                // binary search: pehla point >= h
    while (lo < hi) { const m = (lo + hi) >> 1; this.ring[m].h < h ? (lo = m + 1) : (hi = m); }
    return this.ring[lo % this.ring.length].node;     // wrap-around
  }
}

A2Bloom Filter

What: Bahut kam memory mein “kya ye item set mein hai?” batane wala probabilistic structure. “Definitely not present” ya “probably present.” False positives ho sakte hain, false negatives kabhi nahi; delete nahi hota (counting bloom filter se hota hai).

Kaise: Bit array (m bits) + k hash functions. Add: k positions par bit 1. Check: saari k positions 1 hain to “shayad hai”, koi 0 to “pakka nahi hai.”

class BloomFilter {
  constructor(m = 1 << 20, k = 4) { this.m = m; this.k = k; this.bits = new Uint8Array((m >> 3) + 1); }
  #positions(item) {
    const h1 = hash(item), h2 = hash(item + "#salt") | 1;       // double hashing (hash(): A1)
    return Array.from({ length: this.k }, (_, i) => (h1 + i * h2) % this.m);
  }
  add(item) { for (const p of this.#positions(item)) this.bits[p >> 3] |= 1 << (p & 7); }
  mightContain(item) { return this.#positions(item).every(p => this.bits[p >> 3] & (1 << (p & 7))); }
}

class TokenBucket {

Practical: Health checks (unhealthy hatao), connection draining, L4 vs L7 (Q68, Q96), sticky sessions se bachna (stateless app), global load balancing (Route 53 latency/geo). AWS ALB: round robin + least outstanding requests option.

Requirements: Unique, (kabhi) sortable, short, distributed generation (bina central bottleneck).

// Base62: number -> short string (URL shortener, Q74)
const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
function toBase62(num) {                      // num: BigInt ya Number
  let n = BigInt(num), out = "";
  if (n === 0n) return "0";
  while (n > 0n) { out = ALPHABET[Number(n % 62n)] + out; n /= 62n; }
  return out;
}
function fromBase62(str) { return [...str].reduce((n, c) => n * 62n + BigInt(ALPHABET.indexOf(c)), 0n); }
toBase62(125);           // "21"
toBase62(3521614606207n) // 7 chars

// Snowflake: 64-bit = [41 bits time][10 bits machine][12 bits sequence] -> 4096 ids/ms/machine
class Snowflake {
  constructor(machineId, epoch = 1700000000000n) {
    this.machine = BigInt(machineId) & 1023n; this.epoch = epoch; this.seq = 0n; this.last = -1n;
  }
  next() {
    let now = BigInt(Date.now());
    if (now < this.last) throw new Error("Clock peeche gaya");         // NTP issue
    if (now === this.last) {
      this.seq = (this.seq + 1n) & 4095n;
      if (this.seq === 0n) while ((now = BigInt(Date.now())) <= this.last);   // ms ka sequence khatam: wait
    } else this.seq = 0n;
    this.last = now;
    return ((now - this.epoch) << 22n) | (this.machine << 12n) | this.seq;
  }
}
const gen = new Snowflake(7);  gen.next();       // time-sortable unique id

Trade-offs: URL shortener mein counter + base62 (predictable, enumerable → security ke liye salt/shuffle ya random). Public IDs ke liye UUID/ULID (guess nahi), internal ke liye bigint. Postgres: UUID v4 random inserts B-tree fragment karte hain; UUIDv7 behtar. Clock skew distributed time-based IDs ka risk.

A6Cache Eviction: LRU (O(1)) aur LFU

Eviction policies: Cache full ho to kya hataein?

Policy Hatata hai Best
LRU (Least Recently Used) Sabse purane time se use na hua General purpose (most common)
LFU (Least Frequently Used) Sabse kam baar use hua Stable popularity (hot items)
FIFO Sabse pehle aaya Simple
TTL Expire hue Time-bound data
Random Koi bhi Redis allkeys-random

LRU in O(1): Hash Map + Doubly Linked List (list ka front = most recent, back = LRU).

class Node { constructor(k, v) { this.k = k; this.v = v; this.prev = this.next = null; } }

class LRUCache {
  constructor(capacity) {
    this.cap = capacity; this.map = new Map();
    this.head = new Node(); this.tail = new Node();            // sentinels
    this.head.next = this.tail; this.tail.prev = this.head;
  }
  #remove(n) { n.prev.next = n.next; n.next.prev = n.prev; }
  #addFront(n) { n.next = this.head.next; n.prev = this.head; this.head.next.prev = n; this.head.next = n; }

  get(key) {
    const n = this.map.get(key);
    if (!n) return -1;
    this.#remove(n); this.#addFront(n);                        // recently used bana do
    return n.v;
  }
  put(key, val) {
    let n = this.map.get(key);
    if (n) { n.v = val; this.#remove(n); this.#addFront(n); return; }
    if (this.map.size === this.cap) {                          // full: LRU (tail ke pehle) hatao
      const lru = this.tail.prev; this.#remove(lru); this.map.delete(lru.k);
    }
    n = new Node(key, val); this.map.set(key, n); this.#addFront(n);
  }
}
const c = new LRUCache(2); c.put(1, "a"); c.put(2, "b"); c.get(1); c.put(3, "c");   // key 2 evict
