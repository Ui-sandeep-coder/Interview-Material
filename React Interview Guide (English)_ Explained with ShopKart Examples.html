React Fundamentals 10 questions

1What is React?

What: React is an open-source JavaScript library for building user interfaces (UI). Meta (Facebook) released it in 2013. The core idea: split the screen into small reusable components, and when data changes, React updates the UI by itself.

Why: With plain JavaScript or jQuery you had to update the page manually (document.getElementById(...).innerText = ...) every time data changed. In a big app this became a bug factory (“the cart count updated in the cart but not in the header”).

How: In React you describe what the UI should look like for this data (declarative), and React handles how to update it.

Real project example (ShopKart): Product card, Navbar, Cart and Filter sidebar are separate components. When an item is added, the cartCount state changes and the Navbar badge, the Cart page and the checkout summary all update automatically.

function Navbar({ cartCount }) {
  return <header>ShopKart 🛒 {cartCount}</header>;
}

Interview line: “React is a declarative, component-based library that renders UI from state and uses the Virtual DOM for efficient updates.”

2What are the features of React?

Main features:

  • Component-based architecture: build the UI from small independent pieces. Easy to reuse and test.
  • Virtual DOM: a lightweight copy of the real DOM; only the changed part is updated.
  • JSX: HTML-like syntax inside JavaScript.
  • One-way data flow: data moves from parent to child (props). Easier to debug.
  • Hooks: state and lifecycle in functional components.
  • Huge ecosystem: React Router, Redux Toolkit, React Query, Next.js.
  • Declarative: write what to show, React works out how.

Why these matter: in a team of 10 developers, people can work on different components in parallel. In ShopKart one developer builds ProductCard and another builds Checkout without touching each other’s files.

4Is React a library or a framework?

Answer: a library. React only handles the View layer, rendering the UI. It gives no rules for routing, API calls, form validation or global state.

Why this matters: a framework follows the “Hollywood principle” (“don’t call us, we’ll call you”): you follow its structure. With a library you stay in control.

Real example: in ShopKart we combined React + React Router (routing) + Redux Toolkit (state) + Axios (API) + React Hook Form (forms). A library gives you the freedom to build that stack. Tools like Next.js turn React into a framework (SSR and routing built in).

5What is a SPA (Single Page Application)?

What: a web app where the browser loads only one HTML page. When you navigate, the whole page does not reload; JavaScript only changes the part that needs to change.

Why: in a traditional multi-page site, every click fetches fresh HTML from the server: flicker and slowness. A SPA feels like an app (Gmail, Instagram web).

How: the server sends one index.html plus a JS bundle. React Router looks at the URL and decides which component to show. For data it calls APIs (JSON).

ShopKart example: when you go from /products to /cart, the header and footer stay the same and only the middle content changes. State such as the cart also survives without a reload.

Downside: the initial load can be heavy, and SEO is a challenge (so SSR, Next.js or prerendering is used).

6What is the Virtual DOM?

What: a JavaScript object copy of the real DOM that lives in memory. It is very light because it does no actual browser painting.

Why: updating the real DOM is expensive (layout, repaint). If the whole DOM were rewritten for every small change, the app would be slow.

How (step by step):

  1. State changes.
  2. React builds a new Virtual DOM tree.
  3. It compares the old and new trees (diffing).
  4. Only the differences are applied to the real DOM (patch).

Real example: ShopKart shows a list of 50 products and one product’s price changes. React updates only that one price text node; the other 49 cards are not touched.

const [price, setPrice] = useState(999);
<p>₹{price}</p>

Important clarification: the Virtual DOM is not “magically fast”; a perfectly hand-tuned manual DOM update can be fast too. Its benefit is that the developer does not have to manage the DOM manually, and React batches updates to keep them reasonably fast. Saying this in an interview sounds senior.

8What is JSX?

What: JSX = JavaScript XML. A way to write HTML-like syntax inside JavaScript. It is not real HTML; when compiled it turns into React.createElement() calls (or the modern jsx()).

Why: the UI and its logic live in one place (separation of concerns by feature, not by file type), and the code is readable.

Rules:

  • Return a single parent element (or a Fragment <>...</>).
  • Use className instead of class, and htmlFor instead of for.
  • JS expressions go inside { }.
  • Every tag must be closed (<img />).
function ProductCard({ product }) {
  return (
    <div className="card">
      <h3>{product.name}</h3>
      <p>₹{product.price}</p>
      {product.stock === 0 && <span>Out of stock</span>}
    </div>
  );
}

Security bonus: JSX escapes values by default, which lowers the risk of XSS.

9Why do we use JSX?
  • Readability: writing nested React.createElement('div', {className:'card'}, ...) is painful. JSX shows the visual structure.
  • Logic + UI together: conditions and loops are just JS.
  • Compile-time errors: a wrong tag is caught at build time.
  • Tooling: support in ESLint, TypeScript and Prettier.

It is not mandatory. React works without JSX, but practically 100% of projects use it.

10What is Babel?

What: Babel is a JavaScript compiler/transpiler. It converts modern JS/JSX into JS that browsers can understand.

Why: browsers do not understand JSX. Older browsers may also not understand ES6+ features (arrow functions, optional chaining).

How: it runs inside the build tool (Vite/webpack).

const el = <h1 className="title">Hello</h1>;
const el = React.createElement("h1", { className: "title" }, "Hello");

Real note: these days Vite (esbuild/SWC) is also used, which is faster than Babel; the concept is the same: JSX to JS.

Components 7 questions

11What is a Functional Component?

What: a simple JavaScript function that returns JSX. In modern React, 99% of components are like this.

Why: less code, easy to read, and Hooks give you state and lifecycle too. No this confusion.

function CartBadge({ count }) {
  return <span className="badge">{count}</span>;
}

Real example: ShopKart’s CartBadge, Button, PriceTag and Rating are all functional components.

12What is a Class Component?

What: an ES6 class that extends React.Component; the render() method returns JSX. State is this.state and updates use this.setState().

class Counter extends React.Component {
  state = { count: 0 };
  componentDidMount() { document.title = "Loaded"; }
  render() {
    return <button onClick={() => this.setState({ count: this.state.count + 1 })}>
      {this.state.count}
    </button>;
  }
}

Why you still need to know it today: it appears in legacy codebases, and Error Boundaries can still only be built with class components (there is no Hooks equivalent). In new code use functional components.

Why functional won: logic reuse is easy (custom hooks), and related code stays in one place (subscribe + cleanup in one useEffect), whereas in classes one job was scattered across three lifecycle methods.

14What is a Pure Component?

What: a component that re-renders only when its props or state change in a shallow comparison. In classes it is React.PureComponent; in functional components it is React.memo.

Pure function idea: same input gives the same output, with no side effects.

Why: to stop a child from re-rendering needlessly when the parent re-renders.

const ProductCard = React.memo(function ProductCard({ product }) {
  console.log("render", product.id);
  return <div>{product.name}</div>;
});

Remember: it is a shallow comparison. If you pass a new object/array/function in props on every render, memo will not help (see useCallback, useMemo).

15What is a Higher Order Component (HOC)?

What: a function that takes a component and returns a new enhanced component.

Why: so cross-cutting logic (auth check, logging, loader) does not have to be copied again and again.

function withAuth(Component) {
  return function Protected(props) {
    const { user } = useAuth();
    if (!user) return <Navigate to="/login" />;
    return <Component {...props} user={user} />;
  };
}
const AdminDashboard = withAuth(Dashboard);

Real example: withAuth and withLoader in ShopKart. Library examples: connect() (old Redux), React.memo.

Today: custom hooks and wrapper components are preferred because HOCs cause “wrapper hell” and prop collisions.

16What are Presentational and Container Components?

Presentational: only shows UI, gets data through props, knows nothing about APIs or state. Container: fetches data, manages state and passes it to the presentational component.

// Container
function ProductListContainer() {
  const { data, isLoading } = useProducts();
  if (isLoading) return <Spinner />;
  return <ProductList products={data} />;
}
// Presentational
function ProductList({ products }) {
  return products.map(p => <ProductCard key={p.id} product={p} />);
}

Why: easier testing and reuse. A designer can work on the UI part and a developer on the logic. With hooks this is no longer a formal rule; it lives on as “custom hook + UI”.

17How do you build Reusable Components?

Principles:

  1. Single responsibility: one component, one job.
  2. Customize through props: no hard-coded text or colors.
  3. Composition (children): allow anything inside.
  4. Sensible defaults.
  5. Logic in a hook, UI in the component.
function Button({ variant = "primary", loading = false, children, ...rest }) {
  return (
    <button className={`btn btn-${variant}`} disabled={loading || rest.disabled} {...rest}>
      {loading ? "Please wait..." : children}
    </button>
  );
}
// Use
<Button variant="danger" onClick={removeItem}>Remove</Button>
<Button loading={isPaying}>Pay Now</Button>

Real example: ShopKart has a shared UI library (/components/ui) with Modal, Table, Input and Button. Login, checkout and admin all use the same Button, so a design change happens in one place.

Props & State 7 questions

18What are Props?

What: props = properties. Read-only data passed from a parent to a child. The child cannot modify it.

Why: it makes the component reusable. The same ProductCard can show different products with different data.

<ProductCard name="Nike Shoes" price={4999} inStock />
function ProductCard({ name, price, inStock }) { ... }

Rule: props are immutable. If the child needs a change, it asks the parent through a function prop (callback).

19What is State?

What: a component’s own private memory that changes over time. When state changes, React re-renders the component.

Why: changing a normal variable does not update the UI; a state change signals React.

function Quantity() {
  const [qty, setQty] = useState(1);
  return (
    <>
      <button onClick={() => setQty(q => Math.max(1, q - 1))}>-</button>
      <span>{qty}</span>
      <button onClick={() => setQty(q => q + 1)}>+</button>
    </>
  );
}

Rules: never mutate state directly (arr.push is wrong). Always use the setter and create a new object/array.

20What is the difference between Props and State?
Props State
Comes from outside (from the parent) Internal to the component
Read-only Changed with a setter
Child cannot modify it The component modifies it itself
Like configuration Like memory

Real example: ProductCard receives product as props (the parent decides), but “is the wishlist heart filled?” lives in useState (the card’s own).

Thumb rule: if the data comes from the parent and does not change, it is props. If it changes through user interaction and affects the UI, it is state. If it can be computed from other state, it is a derived value (do not make it state).

21Why is a state update asynchronous?

Reason (performance): React batches multiple setState calls and re-renders once. That is why, right after setCount(count + 1), count still shows the old value: the count of that render is a “snapshot”.

const [count, setCount] = useState(0);
function handle() {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
  console.log(count);
}

function handleCorrect() {
  setCount(c => c + 1);
  setCount(c => c + 1);
  setCount(c => c + 1);   // final: 3
}

Real bug: in ShopKart, double-clicking “Add to cart” quickly increased the quantity by only 1, because a stale value was used. Fix: setQty(q => q + 1). If you need the latest value, use useEffect or flushSync (rare). In React 18 batching also happens inside timeouts and promises.

22How do you pass data from Parent to Child?

Through props. Simple and the most common way.

function ProductPage() {
  const product = { id: 1, name: "Laptop", price: 55000 };
  return <ProductCard product={product} onBuy={() => alert("Buy")} />;
}
function ProductCard({ product, onBuy }) {
  return <div>{product.name} <button onClick={onBuy}>Buy</button></div>;
}

For data that must go many levels deep, use the Context API or state management (to avoid prop drilling).

23How do you pass data from Child to Parent?

In React data does not travel upward; the parent passes a callback function in props and the child calls it.

function Parent() {
  const [filter, setFilter] = useState("");
  return (
    <>
      <FilterBar onChange={setFilter} />
      <ProductList filter={filter} />
    </>
  );
}
function FilterBar({ onChange }) {
  return <input onChange={e => onChange(e.target.value)} placeholder="Search" />;
}

Real example (ShopKart): the user picks a category in FilterSidebar (child), it tells the parent ProductsPage, and the parent updates the API query. This technique is also called “lifting state up”.

24What is Prop Drilling?

What: passing data through many levels of components even though the middle components do not need it.

// App -> Layout -> Header -> UserMenu -> Avatar  (user har jagah pass)
<Layout user={user} /> -> <Header user={user} /> -> <UserMenu user={user} />

Problems: verbose code, hard to refactor, and needless re-renders of the middle components.

Solutions:

  1. Context API (theme, user, language).
  2. Redux Toolkit / Zustand (large shared state).
  3. Component composition (pass children to skip drilling).
  4. React Query for server state.

ShopKart example: the logged-in user is needed by Avatar five levels down. We created AuthContext and called useAuth() in Avatar. The middle components need no props. But do not use Context for every small 2-3 level case; drilling is fine up to 2-3 levels.

Hooks 11 questions

25What are Hooks?

What: Hooks are special functions (names start with use...) that let functional components use state, lifecycle and other React features. They arrived in React 16.8.

Why they were introduced: in class components, reusing logic was hard (HOC/render props), this was confusing, and the code for one feature was scattered across lifecycle methods.

Rules of Hooks:

  1. Call them only at the top level (not inside if/loops/nested functions).
  2. Call them only from React function components or custom hooks.

Why the rules exist: React remembers hooks by their call order. If you put a hook in a condition, the order breaks and state gets matched to the wrong hook.

Common hooks: useState, useEffect, useRef, useMemo, useCallback, useContext, useReducer, useLayoutEffect, useTransition, useId.

26What is useState?

What: the hook for keeping state in a component. [value, setValue] = useState(initial).

function SearchBox() {
  const [query, setQuery] = useState("");
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}

Important points:

  • Lazy initial state: if initialization is expensive, pass a function: useState(() => JSON.parse(localStorage.getItem("cart")) ?? []). It runs only on the first render.
  • Functional update: setCount(c => c + 1) when the new value depends on the old one.
  • Immutable updates for objects/arrays:
setCart(prev => [...prev, newItem]);                       // add
setCart(prev => prev.filter(i => i.id !== id));            // remove
setCart(prev => prev.map(i => i.id === id ? { ...i, qty: i.qty + 1 } : i)); // update

If you set the same value (Object.is equal), React skips the re-render.

27What is useEffect?

What: the hook for running side effects: API calls, subscriptions, timers, DOM manipulation, localStorage, event listeners. It runs after the render.

Why: the render function must stay “pure”. Work like an API call cannot happen inside render; it goes in an effect.

Syntax:

useEffect(() => {
  // effect (setup)
  return () => { /* cleanup */ };
}, [dependencies]);

Real example: ShopKart product details:

function ProductDetails({ productId }) {
  const [product, setProduct] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(`/api/products/${productId}`, { signal: controller.signal })
      .then(r => { if (!r.ok) throw new Error("Failed"); return r.json(); })
      .then(setProduct)
      .catch(e => { if (e.name !== "AbortError") setError(e.message); })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, [productId]);
  ...
}

Tip: for pure data fetching, real projects prefer React Query/RTK Query (cache, retry, dedupe).

28What is useRef?

What: a mutable box ({ current: value }) that stays the same across re-renders, and changing it does not trigger a re-render.

Two main use cases:

  1. Accessing a DOM element: focus, scroll, video play.
  2. Remembering a value without triggering a render: timer id, previous value, an “is mounted” flag.
function LoginForm() {
  const emailRef = useRef(null);
  useEffect(() => { emailRef.current.focus(); }, []);
  return <input ref={emailRef} type="email" />;
}

function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; });
  return ref.current;
}

useState vs useRef: if a change should update the UI, use state; if the UI does not care (for example a debounce timer id), use a ref.

29What is useMemo?

What: it caches the result of an expensive calculation; if the dependencies do not change, it does not recalculate.

const filtered = useMemo(
  () => products.filter(p => p.name.toLowerCase().includes(query.toLowerCase()))
                 .sort((a, b) => a.price - b.price),
  [products, query]
);

Why: filtering and sorting 10,000 products on every keypress and every unrelated state change is wasteful.

Second use: keeping an object/array reference stable so a React.memo child does not re-render needlessly.

Warning: do not put it everywhere. Memoization has its own cost. Measure first (React Profiler). It is a “performance hint”, not a semantic guarantee.

30What is useCallback?

What: it caches a function’s reference (a shortcut for useMemo(() => fn, deps)).

Why: when a component re-renders, a new function is created every time; a React.memo child thinks a prop changed and re-renders too.

const ProductCard = React.memo(({ product, onAdd }) => { ... });

function ProductList({ products }) {
  const [cart, setCart] = useState([]);
  const handleAdd = useCallback(id => {
    setCart(prev => [...prev, id]);
  }, []);
  return products.map(p => <ProductCard key={p.id} product={p} onAdd={handleAdd} />);
}

Remember: useCallback only helps when the child is React.memo (or the function is in a hook dependency). On its own it does nothing.

31What is useContext?

What: a hook to read context data directly at any depth, without prop drilling.

const ThemeContext = createContext("light");

function App() {
  const [theme, setTheme] = useState("light");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Header />
    </ThemeContext.Provider>
  );
}
function ThemeToggle() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>{theme}</button>;
}

Caution: when the Provider’s value changes, all consumers re-render. So do not put frequently changing data in Context; split context into small ones (Auth, Theme, Cart) and useMemo the value.

32What is a Custom Hook?

What: your own function whose name starts with use and which uses other hooks inside. A way to reuse logic.

Why: instead of copy-pasting the same “fetch + loading + error” or “localStorage sync” code in five components, write one hook.

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try { return JSON.parse(localStorage.getItem(key)) ?? initial; }
    catch { return initial; }
  });
  useEffect(() => { localStorage.setItem(key, JSON.stringify(value)); }, [key, value]);
  return [value, setValue];
}

function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

ShopKart hooks: useAuth(), useCart(), useDebounce(), useOnlineStatus(), useProducts(). Each hook call has its own state (it is not shared).

33What is useReducer?

What: an advanced version of useState where the update logic lives in a reducer function (state, action) => newState.

When to use: when state is complex (several related fields) or the next state depends on the previous one. Cart, multi-step forms, checkout flow.

function cartReducer(state, action) {
  switch (action.type) {
    case "ADD": {
      const exists = state.items.find(i => i.id === action.item.id);
      return {
        ...state,
        items: exists
          ? state.items.map(i => i.id === action.item.id ? { ...i, qty: i.qty + 1 } : i)
          : [...state.items, { ...action.item, qty: 1 }],
      };
    }
    case "REMOVE": return { ...state, items: state.items.filter(i => i.id !== action.id) };
    case "CLEAR":  return { items: [] };
    default: return state;
  }
}

const [state, dispatch] = useReducer(cartReducer, { items: [] });
dispatch({ type: "ADD", item: product });

Why: all update logic is in one place, it is easy to test (pure function), and the identity of dispatch is stable.

34What is useLayoutEffect?

What: the same as useEffect, but it runs synchronously after the DOM update and before the browser paints.

Difference: useEffect runs after paint (async); useLayoutEffect runs before paint (blocking).

When: when you must measure the DOM and adjust the layout immediately with no flicker: tooltip position, dropdown height, scroll-position restore.

useLayoutEffect(() => {
  const { height } = boxRef.current.getBoundingClientRect();
  setTooltipTop(-height - 8);
}, []);

Warning: it blocks rendering, so use useEffect by default. It can also warn during SSR (Next.js).

35What is useImperativeHandle?

What: it lets a parent use ref to access a few controlled methods of the child (not the whole DOM node).

function FancyInput({ ref }) {
  const inputRef = useRef();
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    clear: () => (inputRef.current.value = ""),
  }));
  return <input ref={inputRef} />;
}

// Parent
const ref = useRef();
<FancyInput ref={ref} />
<button onClick={() => ref.current.clear()}>Reset</button>

Real use: a Modal’s open()/close(), a form’s reset(), a video player’s play(). It is used rarely; first try to solve things with props/state.

useEffect Deep Questions 6 questions

36Explain the useEffect lifecycle.

Flow of a functional component:

  1. Render: the component function runs and JSX is produced.
  2. Commit: React updates the DOM.
  3. Paint: the browser shows it on screen.
  4. Effect runs: the useEffect callback runs.
  5. If a dependency changed: first the previous cleanup, then the new effect.
  6. On unmount: cleanup runs.

Mapping to the class lifecycle:

Class useEffect
componentDidMount useEffect(fn, [])
componentDidUpdate useEffect(fn, [dep])
componentWillUnmount return () => {} cleanup 
useEffect(() => {
  console.log("Mounted or productId changed:", productId);
  return () => console.log("Cleanup:", productId);
}, [productId]);

Strict Mode (development): React 18+ mounts, unmounts and mounts the component again in dev to check that cleanup is correct. That is why the effect seems to run twice (not in production). It is not a bug; it helps you catch wrong cleanup.

37What is the dependency array?

It tells React when the effect should run again.

Form Behaviour
useEffect(fn) After every render
useEffect(fn, []) Only on mount (once)
useEffect(fn, [a, b]) On mount and whenever a or b changes

Rule: every prop/state/function you use inside the effect must be in the dependencies. The ESLint plugin react-hooks/exhaustive-deps helps. If you leave one out you get a stale closure bug (old value).

useEffect(() => { fetchProducts(query); }, []);
useEffect(() => { fetchProducts(query); }, [query]);
38What is the use of an empty dependency array?

[] means: run once when the component mounts, with cleanup on unmount.

Use cases:

  • Initial data load (fetch categories when the page opens)
  • Adding event listeners (window.resize, scroll)
  • Initializing WebSocket / analytics
  • Auto-focus
useEffect(() => {
  const onResize = () => setWidth(window.innerWidth);
  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize);
}, []);

Mistake: using state/props inside an effect with []: it will always see the value from the first render (stale closure).

39When does an infinite loop happen?

Case 1: no dependency array and the effect sets state.

useEffect(() => { setCount(count + 1); });   // render -> effect -> setState -> render...

Case 2: a dependency that is a new object/array/function on every render.

const filters = { category: "shoes" };
useEffect(() => { fetchProducts(filters); setProducts(...); }, [filters]); // loop!

Fix:

  • Use primitive dependencies: [filters.category]
  • Stabilize references with useMemo / useCallback
  • Move the object/function outside the component
  • Use the functional update setX(prev => ...) so the state is not a dependency

Real bug (ShopKart): the product-list API call fired 1000 times because a params object was in the dependencies. The Network tab showed a flood of requests and the backend rate-limited us. Fix: pass the two primitives [category, page].

40What is the cleanup function?

What: the function returned from an effect. It runs before the effect runs again and on unmount.

Why: to stop whatever the effect started: timers, listeners, subscriptions, requests.

useEffect(() => {
  const id = setInterval(() => setSeconds(s => s + 1), 1000);
  return () => clearInterval(id);      // cleanup
}, []);

useEffect(() => {
  const socket = new WebSocket(url);
  socket.onmessage = e => setOrders(o => [...o, JSON.parse(e.data)]);
  return () => socket.close();
}, [url]);

Real example: the “Flash sale ends in” countdown in ShopKart: without cleanup the timer keeps running even after you leave the page.

Symptoms: the app slowly gets slower, the tab’s memory grows, and bugs like “state update on an unmounted component”.

setInterval / setTimeout clearInterval/Timeout in cleanup
addEventListener removeEventListener
An API call that sets state on response AbortController

Performance Optimization 10 questions

42What is React.memo?

What: a higher-order component that memoizes a component. If props are the same, the re-render is skipped.

const ProductCard = React.memo(function ProductCard({ product, onAdd }) {
  return <div onClick={() => onAdd(product.id)}>{product.name}</div>;
});

Custom comparison: React.memo(Comp, (prev, next) => prev.product.id === next.product.id).

When it helps: the component is heavy, and the parent re-renders often while props change rarely. When it does not: props are new every time (inline object/function) or the component is very light.

Real case: in ShopKart, typing in the search box re-rendered the parent and also 200 ProductCards. With React.memo + useCallback only the search box re-rendered.

43When do you use useMemo?
  • Heavy calculation: filter/sort/group on a big list, chart data transforms, tax/discount computation.
  • An object/array that goes to a React.memo child as props or into a hook dependency.
  • Do not use it for simple calculations (a + b) or when you have not measured.
const cartTotal = useMemo(
  () => cart.reduce((sum, i) => sum + i.price * i.qty, 0),
  [cart]
);

Test: use console.time or the Profiler to see if the calculation takes more than 1 ms. Only then memoize.

44When do you use useCallback?
  • When passing a function as a prop to a React.memo child.
  • When the function is a dependency of a useEffect/useMemo.
  • When a custom hook returns a function that the consumer will use as a dependency.

When not: a plain onClick={() => ...} on a DOM element gains nothing.

const fetchProducts = useCallback(async () => {
  const res = await api.get("/products", { params: { category } });
  setProducts(res.data);
}, [category]);

useEffect(() => { fetchProducts(); }, [fetchProducts]);
45How do you optimize a React application?

Step-by-step approach (measure first, then fix):

  1. Measure: React DevTools Profiler, Lighthouse, Chrome Performance tab, Web Vitals (LCP, INP, CLS).
  2. Reduce re-renders: React.memo, useMemo, useCallback, move state down (state colocation), split Context.
  3. Reduce bundle size: code splitting (React.lazy), tree-shaking, remove heavy libraries (moment → date-fns/dayjs), bundle analyzer.
  4. Big lists: virtualization (react-window), pagination, infinite scroll.
  5. Network: caching (React Query), debounced search, parallel requests, compression, CDN.
  6. Images: WebP/AVIF, loading="lazy", proper sizes.
  7. Production build: npm run build, gzip/brotli.
  8. Modern React: useTransition, useDeferredValue, Suspense, React Compiler (auto-memoization).

Interview answer structure: “I profile first, find the bottleneck, then apply a targeted fix.” This shows maturity.

46Why does a re-render happen?

A component re-renders when:

  1. Its own state changes (setState).
  2. The parent re-rendered (even if the props are the same, unless memoized).
  3. Props change.
  4. A context value changes (for components that consume it).
  5. A custom hook’s state changes (that is the component’s state too).

Wrong belief: “the child renders only when its props change.” No: if the parent renders, the child does too (by default). A re-render means the function runs again, not necessarily a DOM update. React diffs and touches the DOM only if the output changed.

47How do you avoid unnecessary re-renders?
  1. Keep state where it is needed (colocation): put the search input state in a separate SearchBox component, not the whole page.
  2. React.memo + stable props (useCallback, useMemo).
  3. Children pattern:
function Timer({ children }) {
  const [time, setTime] = useState(0);
  return <div>{time}{children}</div>;
}
  1. Split Context: separate UserContext and ThemeContext; a theme change does not affect user consumers.
  2. Selectors (Redux): useSelector(s => s.cart.items.length), not the whole store.
  3. Give correct keys, avoid inline objects/arrays (when the child is memoized).
  4. Do not store derived state; compute it during render.
  5. Debug: React DevTools > “Highlight updates”, Profiler, why-did-you-render.
48What is Debouncing?

What: running a function only after the user pauses for a delay. All the calls in between are ignored.

Why: typing “iphone” in a search box would fire 6 useless API calls (i, ip, iph…). Debounce makes it one call after the user stops.

function Search() {
  const [q, setQ] = useState("");
  const debounced = useDebounce(q, 500);

  useEffect(() => {
    if (!debounced) return;
    const controller = new AbortController();
    fetch(`/api/search?q=${debounced}`, { signal: controller.signal })
      .then(r => r.json()).then(setResults).catch(() => {});
    return () => controller.abort();
  }, [debounced]);

  return <input value={q} onChange={e => setQ(e.target.value)} />;
}

Use cases: search/autocomplete, form auto-save, window resize handlers.

49What is Throttling?

What: letting a function run at most once per fixed interval, no matter how many times the event fires.

Debounce vs Throttle:

  • Debounce: “wait, run when the user is quiet.”
  • Throttle: “run once every 300 ms, even if the user keeps going.”

Use cases: scroll (infinite scroll position checks), mouse move, resize, stopping “Like” button spam, analytics events.

function throttle(fn, limit) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= limit) { last = now; fn(...args); }
  };
}
window.addEventListener("scroll", throttle(checkLoadMore, 300));
50What is Lazy Loading?

What: loading resources (components, images, routes) only when they are needed, not all at the start.

Why: a smaller initial bundle makes the app open faster (better LCP).

import { lazy, Suspense } from "react";
const AdminDashboard = lazy(() => import("./pages/AdminDashboard"));

<Suspense fallback={<Spinner />}>
  <Routes>
    <Route path="/admin" element={<AdminDashboard />} />
  </Routes>
</Suspense>

<img src={product.image} loading="lazy" alt={product.name} />

ShopKart: why make a customer download the 400 KB chart library used by the admin dashboard? We lazy-loaded the admin page and the home page became 40% lighter.

51What is Code Splitting?

What: breaking one big JS bundle into small chunks that load when needed. The technique that makes lazy loading possible.

Types:

  1. Route-based splitting (most common): each page is a chunk.
  2. Component-based: modals, charts, rich-text editors when the user opens them.
  3. Vendor splitting: libraries in a separate chunk (cache benefit).
// Heavy library on-demand
const handleExport = async () => {
  const { default: jsPDF } = await import("jspdf");
  new jsPDF().text("Invoice", 10, 10).save("invoice.pdf");
};

Tools: Vite/webpack automatically create chunks at import(). Use rollup-plugin-visualizer or webpack-bundle-analyzer to inspect the bundle.

Rendering 6 questions

52What is Rendering?

What: rendering = React running a component function to produce JSX/UI description and then showing it on screen.

Two phases:

  1. Render phase: component functions run and a new Virtual DOM tree is built (pure calculation, no DOM touched).
  2. Commit phase: React updates the real DOM according to the diff. Effects run right after this.

Initial render (the app’s first time) and re-render (state/props change). In server-side rendering (SSR) this happens on the server and HTML is sent.

Remember: the render function must be pure (same input, same output); no API calls, Math.random() or DOM changes in it.

53When does a re-render happen?

Same as Q46: state changed, parent rendered, props/context changed. React 18 bonus: automatic batching: multiple setState calls inside one event produce a single re-render.

function handleClick() {
  setCount(c => c + 1);
  setFlag(f => !f);
}

How you verify: put a console.log("Rendered") at the top of the component, or use React DevTools > Profiler > “Record why each component rendered”.

54What is Conditional Rendering?

What: showing different UI based on a condition.

function ProductList({ products, loading, error }) {
  if (loading) return <Skeleton />;                 // 1. early return
  if (error) return <ErrorMessage text={error} />;
  if (!products.length) return <p>No products found</p>;

  return (
    <>
      {products.map(p => <ProductCard key={p.id} product={p} />)}
      {user?.isAdmin && <AdminTools />}              // 2. && operator
      {isLoggedIn ? <Logout /> : <Login />}           // 3. ternary
    </>
  );
}

Gotcha: {count && <Badge />} prints 0 on screen when count = 0. Use {count > 0 && <Badge />}.

Real flow (ShopKart): loading shows a skeleton, error shows a retry button, empty shows a “Browse products” CTA, success shows the list. Always handle these 4 states.

55How do you render a List?

Convert an array to JSX elements with map() and give every item a unique key.

<ul>
  {orders.map(order => (
    <li key={order.id}>
      #{order.id} - {order.status}
    </li>
  ))}
</ul>

Tips:

  • Filter + map chain: items.filter(i => i.inStock).map(...).
  • For big lists (1000+) use virtualization.
  • The key must always be a stable, unique ID (the DB id).
56Why do you use the key prop?

What: key is a special prop that tells React which item in the list is which.

Why: during reconciliation React compares the old and new lists. With keys it understands whether an item was added, removed or only moved, and it reuses existing components. Without keys the whole list may be recreated or updated wrongly.

How:

{cart.map(item => <CartItem key={item.id} item={item} />)}

Real bug: the cart had 3 items and each had a quantity input. We deleted the first item, but the key was the index, so the second item’s input showed the first one’s quantity. Using item.id as the key fixed it. A key does not arrive in props (props.key is undefined).

57Why avoid the index as a key?

When the list is reordered, inserted into, deleted from or filtered, the indexes change. React treats the component at the same index as “the same item”, so state and DOM stick to the wrong item.

items.map((item, index) => <Row key={index} item={item} />)

items.map(item => <Row key={item.id} item={item} />)

When an index key is fine: a static list that is never reordered or deleted from, whose items have no internal state. If there is no ID, assign one at creation with crypto.randomUUID() (never generate a random key inside render; it is new every render and everything remounts).

Forms 6 questions

58What is a Controlled Component?

What: a form input whose value is controlled by React state. Every keystroke onChange updates state, and the input shows value={state}. React state is the “single source of truth”.

function Login() {
  const [form, setForm] = useState({ email: "", password: "" });
  const handleChange = e => setForm(f => ({ ...f, [e.target.name]: e.target.value }));
  const handleSubmit = e => { e.preventDefault(); api.post("/login", form); };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" value={form.email} onChange={handleChange} />
      <input name="password" type="password" value={form.password} onChange={handleChange} />
      <button disabled={!form.email || !form.password}>Login</button>
    </form>
  );
}

Pros: live validation, enabling/disabling the button, formatting (phone number mask), conditional fields. Cons: big forms re-render on every keystroke.

59What is an Uncontrolled Component?

What: an input whose value is managed by the DOM itself; we read it with a ref on submit.

function FileUpload() {
  const fileRef = useRef();
  const handleSubmit = e => {
    e.preventDefault();
    console.log(fileRef.current.files[0]);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input type="file" ref={fileRef} />
      <button>Upload</button>
    </form>
  );
}

When: file inputs (always uncontrolled), simple forms without live validation, and big forms (React Hook Form uses uncontrolled inputs internally, which is why it is fast).

60How do you do form validation?

Levels:

  1. HTML5: required, pattern, minLength.
  2. Manual (with state): an errors object.
  3. Library (recommended): React Hook Form + Zod/Yup.
  4. Server-side validation is always required.
const validate = v => {
  const e = {};
  if (!/^\S+@\S+\.\S+$/.test(v.email)) e.email = "Enter a valid email";
  if (v.password.length < 8) e.password = "At least 8 characters";
  return e;
};

UX best practices: show an error after the field is touched (blur) or on submit, make messages clear and specific, disable the button while submitting, and map server errors to fields (e.g. “Email already registered”).

61Have you used React Hook Form?

What: a performance-focused form library. Uncontrolled inputs + refs give fewer re-renders.

import { useForm } from "react-hook-form";

function Checkout() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm();
  const onSubmit = async data => { await api.post("/orders", data); };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register("phone", { required: "Phone is required", pattern: { value: /^[6-9]\d{9}$/, message: "Valid number" } })} />
      {errors.phone && <p>{errors.phone.message}</p>}
      <button disabled={isSubmitting}>Place order</button>
    </form>
  );
}

Features: watch, setValue, reset, Controller (for controlled libraries such as MUI/antd), useFieldArray (dynamic rows), schema resolvers (Zod/Yup).

Why use it: in a 30-field form, manual useState re-renders the whole form on every keystroke; with RHF it does not.

62What is Formik?

What: a popular form library that manages values, errors, touched state and submit handling. useFormik or the <Formik> component.

const formik = useFormik({
  initialValues: { email: "" },
  validationSchema: Yup.object({ email: Yup.string().email().required() }),
  onSubmit: values => api.post("/subscribe", values),
});
<input name="email" onChange={formik.handleChange} onBlur={formik.handleBlur} value={formik.values.email} />

Formik vs RHF: Formik uses a controlled approach (more re-renders); RHF is faster with a smaller bundle. New projects usually prefer RHF, but legacy projects still use Formik.

63How do you validate with Zod or Yup?

Both are schema validation libraries: define the schema once and validate forms and API responses. Zod is TypeScript-first (it infers types from the schema).

import { z } from "zod";
import { zodResolver } from "@hookform/resolvers/zod";

const schema = z.object({
  name: z.string().min(2, "Name must be at least 2 letters"),
  email: z.string().email("Enter a valid email"),
  password: z.string().min(8).regex(/[A-Z]/, "One capital letter is required"),
  confirm: z.string(),
}).refine(d => d.password === d.confirm, { path: ["confirm"], message: "Passwords do not match" });

type FormData = z.infer<typeof schema>;

const { register, handleSubmit, formState: { errors } } =
  useForm<FormData>({ resolver: zodResolver(schema) });

Why: validation rules in one place, reusable, with type safety. Yup’s syntax is almost the same (Yup.object({ email: Yup.string().email().required() })).

Event Handling 4 questions

64What is Event Handling?

Running a function on user actions (click, type, submit, hover). In React events are camelCase and you pass a function (not a string).

<button onClick={handleAddToCart}>Add</button>
<button onClick={handleAddToCart()}>Add</button>
<button onClick={() => handleAdd(product.id)}>Add</button>

e.preventDefault() stops the form submit/link default, e.stopPropagation() stops bubbling.

65What is a Synthetic Event?

What: React’s cross-browser wrapper around the native browser event (SyntheticEvent). The interface stays the same: e.target, e.preventDefault(), e.stopPropagation().

Why: React hides the event differences between browsers.

Event delegation: React does not attach a listener to every element; it attaches one listener at the root and handles events from there (efficient). For the native event use e.nativeEvent.

Note: until React 16 there was event pooling (the event became null on async access); React 17+ removed pooling.

66How are onClick and onChange used?
  • onClick: on click (button, card, link).
  • onChange: when an input’s value changes (every keystroke, select, checkbox). The core of a controlled input.
function QuantityInput() {
  const [qty, setQty] = useState(1);
  return (
    <>
      <input type="number" value={qty} onChange={e => setQty(Number(e.target.value))} />
      <button onClick={() => alert(`Adding ${qty}`)}>Add to cart</button>
    </>
  );
}

Note: React’s onChange behaves like the native input event (on every keystroke), not on blur. For a checkbox use e.target.checked.

67What is Event Bubbling?

The event runs on the target first, then bubbles up to the parent.

<div onClick={() => console.log("Card clicked")}>
  <button onClick={e => { e.stopPropagation(); addToCart(); }}>Add to cart</button>
</div>

Real problem: in ShopKart, clicking the card opens the product detail page, but clicking the “Add to cart” button inside the card also opened the page. Fix: e.stopPropagation() in the button’s handler.

Capturing: the reverse flow (parent to child). You can catch it with onClickCapture. Delegation: thanks to bubbling, a listener on one parent can handle all of its children.

React Router 8 questions

68What is React Router?

What: React’s standard routing library. It decides which component to show based on the URL, without a page reload (SPA).

Why: without a router everything lives on one URL; the back button, bookmarking and sharing links would not work.

import { BrowserRouter, Routes, Route } from "react-router-dom";

Core pieces: BrowserRouter, Routes, Route, Link/NavLink, useNavigate, useParams, useSearchParams, Outlet. (Note: v6.4+ / v7 also have createBrowserRouter + data APIs (loader/action).)

69What is BrowserRouter?

What: a router that uses the HTML5 History API and gives clean URLs (/products/12).

Alternatives:

  • HashRouter: /#/products (needs no server config, the old approach)
  • MemoryRouter: testing or non-browser

70What is a Route?

What: a rule that maps a URL path to a component.

<Route path="/cart" element={<Cart />} />
<Route path="/orders/:orderId" element={<OrderDetails />} />   {/* dynamic */}

71What is the difference between Link and NavLink?
  • <Link to="/cart">: navigation without a reload (an anchor <a href> reloads the page).
  • <NavLink>: a Link that also knows its active state, so you can highlight the menu.
<NavLink

  className={({ isActive }) => (isActive ? "nav active" : "nav")}
>
  My Orders

What: part of the URL is a variable (:id) that you read with useParams.

<Route path="/products/:productId" element={<ProductDetails />} />

  const { productId } = useParams();
  const { data: product } = useQuery({

73What is Nested Routing?

What: routes inside routes. The parent route provides the layout, and the child route renders in its <Outlet />.

<Routes>
  <Route path="/admin" element={<AdminLayout />}>      {/* sidebar + header */}
    <Route index element={<Dashboard />} />             {/* /admin */}
    <Route path="products" element={<AdminProducts />} />   {/* /admin/products */}
    <Route path="orders" element={<AdminOrders />} />

function AdminLayout() {
  return (
    <div className="admin">
      <Sidebar />
      <main><Outlet /></main>
    </div>
  );
}

Why: you do not rewrite the layout again and again, and the sidebar does not re-mount on a page change.

74What is the useNavigate Hook?

What: a hook to navigate from code (programmatically): after a button click, a successful login or a form submit.

const navigate = useNavigate();

const handleLogin = async () => {
  await login(credentials);
  navigate("/dashboard", { replace: true });
};

navigate(-1);                       // back
navigate("/orders", { state: { from: "checkout" } });

replace: true: after login, if the user presses back they will not return to the login page. Link vs navigate: if navigation should happen on click, use Link (better accessibility); if it happens after some logic, use useNavigate.

75How do you build Protected Routes?

Idea: a wrapper route that checks whether the user is logged in; if not, it redirects to login.

import { Navigate, Outlet, useLocation } from "react-router-dom";

function ProtectedRoute({ allowedRoles }) {
  const { user, loading } = useAuth();
  const location = useLocation();

  if (loading) return <Spinner />;
  if (!user) return <Navigate to="/login" state={{ from: location }} replace />;
  if (allowedRoles && !allowedRoles.includes(user.role)) return <Navigate to="/403" replace />;
  return <Outlet />;
}

<Routes>
  <Route path="/login" element={<Login />} />
  <Route element={<ProtectedRoute />}>
    <Route path="/orders" element={<Orders />} />
  </Route>
  <Route element={<ProtectedRoute allowedRoles={["admin"]} />}>
    <Route path="/admin" element={<AdminLayout />} />
  </Route>
</Routes>

Return after login: navigate(location.state?.from?.pathname || "/").

Very important: frontend route protection is only UX, not security. Real security must be on the backend API (token + role check on every request).

Context API 4 questions

76What is the Context API?

What: React’s built-in mechanism to share data at any level of the component tree without passing props.

Three steps: createContext → Provider (supply the value) → useContext (read the value).

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const login = async creds => { const { data } = await api.post("/login", creds); setUser(data.user); };
  const logout = () => setUser(null);
  const value = useMemo(() => ({ user, login, logout }), [user]);
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export const useAuth = () => {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("Use useAuth inside AuthProvider");
  return ctx;
};
77Why do you use the Context API?
  • To remove prop drilling.
  • For app-wide data that changes rarely: theme, language, logged-in user, feature flags.
  • It is built in, so no extra library.

Limits: when the value changes all consumers re-render; there is no selector support; for big, frequently changing state (a cart with 100 updates per minute) Redux/Zustand is better. Best practice: small focused contexts, a useMemo value, and a custom hook wrapper.

79What is Global State?

What: state that many different components/pages need, not limited to one component.

Examples (ShopKart): logged-in user, cart items, theme, notifications, selected language.

Categories of state:

  1. Local UI state: is a modal open → useState.
  2. Shared client state: cart, filters → Context/Redux/Zustand.
  3. Server state: products, orders → React Query/RTK Query (caching, refetch).
  4. URL state: page, category → URL params.

Rule: keep state as local as possible; make it global only when 2+ distant components truly need it. Putting everything in Redux is an anti-pattern.

Redux 12 questions

80What is Redux?

What: a predictable state container. The whole app’s state lives in one central store and can change only through actions → reducers.

Why: in a big app, when state is scattered, you cannot tell “who changed this value”. In Redux every change is traceable (every action is visible in Redux DevTools).

Three principles: single source of truth, state is read-only (change only through actions), reducers are pure functions.

81Explain the Redux flow.

Flow: UI → dispatch(action) → (middleware) → reducer → new store state → UI re-renders (useSelector).

ShopKart “Add to cart”:

  1. The user clicks the “Add” button.
  2. The component calls dispatch(addToCart(product)).
  3. The action { type: "cart/addToCart", payload: product } goes to the reducer.
  4. The reducer builds the new cart state.
  5. The store updates; components that use useSelector(selectCartCount) (Navbar badge, Cart page) re-render.

This is unidirectional data flow, which is why bugs are easy to trace.

82What is a Store?

What: the single object that holds the whole app’s state and provides getState(), dispatch() and subscribe().

  reducer: { cart: cartReducer, auth: authReducer },

83What is an Action?

What: a plain object that says what happened. type is required, payload is optional.

{ type: "cart/addToCart", payload: { id: 1, name: "Shoes", price: 2999 } }

Action creator: a function that builds actions, e.g. addToCart(product). In RTK createSlice generates them automatically.

Naming convention: domain/event, e.g. cart/addToCart, auth/loggedOut.

84What is a Reducer?

What: a pure function (state, action) => newState. It looks at the action and returns the new state.

Rules: pure (same input, same output), no side effects (API, random, Date), do not mutate state (make a new copy).

function cartReducer(state = { items: [] }, action) {
  switch (action.type) {
    case "cart/addToCart":
      return { ...state, items: [...state.items, action.payload] };
    default:
      return state;
  }
}

In RTK: thanks to the Immer library you can write “mutating” syntax (state.items.push(...)) and it is applied immutably under the hood.

85What is Dispatch?

What: the function that sends an action to the store. The only way to change state.

const dispatch = useDispatch();
<button onClick={() => dispatch(addToCart(product))}>Add</button>

With thunk you can also dispatch a function: dispatch(fetchProducts()).

86What is Middleware?

What: a layer between dispatching an action and it reaching the reducer. Async logic, logging, analytics, API calls and error reporting happen here.

Examples: redux-thunk (async functions; default in RTK), redux-saga, a logger, RTK listener middleware.

const logger = store => next => action => {
  console.log("dispatching", action);
  const result = next(action);
  console.log("next state", store.getState());
  return result;
};

Why it is needed: the reducer must be pure, so API calls have to go somewhere else; middleware is that place.

87What is Redux Toolkit?

What: the official, recommended way to write Redux. It reduces boilerplate and gives best practices by default.

What it provides:

  • configureStore (DevTools + thunk + checks automatically)
  • createSlice (reducer + actions in one place)
  • createAsyncThunk (async API handling)
  • Immer (mutating syntax, immutable result)
  • createEntityAdapter, RTK Query (data fetching + caching)

Before vs now: earlier you wrote action types, action creators and switch-case reducers separately (a lot of boilerplate). With RTK a slice is about 10 lines.

88What is createSlice?

What: a function to define a piece of state (a slice): name, initialState, reducers. Actions and the reducer are generated automatically.

import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",
  initialState: { items: [] },
  reducers: {
    addToCart(state, action) {
      const item = state.items.find(i => i.id === action.payload.id);
      if (item) item.qty += 1;                        // Immer: mutate allowed
      else state.items.push({ ...action.payload, qty: 1 });
    },
    removeFromCart(state, action) {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
    clearCart: state => { state.items = []; },
  },
});

export const { addToCart, removeFromCart, clearCart } = cartSlice.actions;
export default cartSlice.reducer;
export const selectCartCount = s => s.cart.items.reduce((n, i) => n + i.qty, 0);

What: the RTK function to create a store. It combines reducers and applies sensible defaults: Redux DevTools, the thunk middleware, and immutability/serializability checks in dev.

90What is createAsyncThunk?

What: an RTK helper to handle an async operation (API call) in Redux. It automatically creates 3 actions: pending, fulfilled, rejected.

export const fetchProducts = createAsyncThunk(
  "products/fetch",
  async (category, { rejectWithValue }) => {
    try {
      const { data } = await api.get("/products", { params: { category } });
      return data;
    } catch (err) {
      return rejectWithValue(err.response?.data?.message || "Server error");
    }
  }
);

const productsSlice = createSlice({
  name: "products",
  initialState: { list: [], status: "idle", error: null },
  reducers: {},
  extraReducers: builder => {
    builder
      .addCase(fetchProducts.pending,   s => { s.status = "loading"; })
      .addCase(fetchProducts.fulfilled, (s, a) => { s.status = "succeeded"; s.list = a.payload; })
      .addCase(fetchProducts.rejected,  (s, a) => { s.status = "failed"; s.error = a.payload; });
  },
});

// Component
useEffect(() => { dispatch(fetchProducts("shoes")); }, [dispatch]);

Why: the loading/success/error boilerplate in one standard pattern. (Today, for server data, RTK Query or React Query is even easier.)

Problem: sequential calls are slow (the sum of times). In parallel the total time is that of the slowest call.

98What is JWT?

What: JSON Web Token: a signed token string that carries identity claims. Three parts: header.payload.signature.

eyJhbGciOi... . eyJ1c2VySWQiOjEyLCJyb2xlIjoiYWRtaW4ifQ . SflKxwRJSM...
 (algo)          (data: userId, role, exp)                (tamper-proof signature)

Why: the server does not need to keep every user’s session in memory (stateless). The token carries the info, and the signature verifies it.

100How do you implement the Login flow in React?

Flow:

  1. The user enters email/password → POST /auth/login.
  2. The server verifies credentials and returns an access token (response) and a refresh token (httpOnly cookie).
  3. The frontend keeps the user in state/context and the access token in memory.
  4. Every API call carries Authorization: Bearer <token>.
  5. On a 401, get a new token from the refresh endpoint, then retry the original request.
  6. On a page refresh, restore the session with /auth/me or the refresh endpoint (a loading state during this).
  7. On logout, clear the cookie on the server and clear state.
export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    api.get("/auth/me").then(r => setUser(r.data)).catch(() => setUser(null)).finally(() => setLoading(false));
  }, []);

  const login = async creds => {
    const { data } = await api.post("/auth/login", creds);
    setAccessToken(data.accessToken);
    setUser(data.user);
  };
  const logout = async () => { await api.post("/auth/logout"); setAccessToken(null); setUser(null); };

  return <AuthContext.Provider value={{ user, loading, login, logout }}>{children}</AuthContext.Provider>;
}

Interceptor (401 refresh): in the response interceptor call /auth/refresh and retry the original request; allow only one refresh at a time (queue) to avoid races.

Advanced React 8 questions

109What is Reconciliation?

What: the process by which React compares the old and new Virtual DOM trees to decide the minimum change needed in the real DOM.

Rules (heuristics):

  1. Different element type (div → span, A → B component): the old tree is destroyed and a new one created (state is lost).
  2. Same type: only the changed attributes/props are updated.
  3. key in lists: to identify items.

Real impact: if you wrap a component in different types conditionally, its state resets. That is why you should not define a component inside another component (a new type on every render → remount → input loses focus).

110What is the Diffing Algorithm?

Finding the differences between two trees. A generic tree diff is O(n^3), which is far too slow. React built a heuristic O(n) algorithm based on 2 assumptions:

  1. Different type = different tree. Replace directly, without a detailed comparison.
  2. The developer provides a key to say which child is stable.

The comparison is level by level (at the same level). So if you move an element to a different level of the tree, React does not move it; it destroys and creates it.

111What is React Fiber?

What: the new reconciliation engine of React 16. It splits rendering work into small units of work (fibers).

The earlier problem: in the old stack reconciler, once a render started it could not be stopped until finished; a big tree froze the UI (typing lag).

With Fiber:

  • Rendering is interruptible (pause, resume, abort).
  • Priority: user typing/clicks are high priority, data updates are low.
  • Concurrent features (useTransition, Suspense) are built on it.

Simple analogy: React used to do a 1-hour job without a break; now it works in 5-minute pieces and checks in between for urgent things (a user click).

112What are Portals?

What: rendering a component’s children outside the parent’s DOM hierarchy (into another DOM node), while in the React tree (events, context) it still stays inside the parent.

import { createPortal } from "react-dom";

Why: because of the parent’s overflow: hidden or z-index stacking context, a modal/tooltip/dropdown gets clipped. A portal moves it to the body level. Use: modals, toasts, tooltips, dropdown menus.

114What are Error Boundaries?

What: a special class component that catches errors during rendering in its child tree and shows a fallback UI instead of crashing.

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logToSentry(error, info); }
  render() {
    return this.state.hasError ? <h2>Something went wrong. Please refresh the page.</h2> : this.props.children;
  }
}

<ErrorBoundary><RecommendationWidget /></ErrorBoundary>

What it does not catch: errors in event handlers (use try/catch), async code (setTimeout, promises), SSR errors, and errors in the boundary itself.

Real use: in ShopKart the recommendations widget crashed, but the whole checkout page did not go white; only that box showed “Unavailable”. In practice the react-error-boundary library is used (hooks-style useErrorBoundary, resetKeys).

115What is Suspense?

What: letting a component wait (for code or data) and showing a fallback UI meanwhile.

<Suspense fallback={<Spinner />}>
  <Reports />
</Suspense>

Use: code splitting with React.lazy; Suspense-enabled data libraries (React Query useSuspenseQuery, Relay, Next.js, React 19 use()). Benefit: declarative loading UI, no if (loading) in every component. Multiple Suspense boundaries allow part-by-part loading, and it is the base of streaming SSR.

What: a React 18 feature where React can prepare several updates with priorities and interrupt rendering when needed, keeping the UI responsive.

APIs:

120How do you handle multiple API calls?

Decision tree:

  • Independent calls: Promise.all / useQueries (parallel).
  • Others should still show if one fails: Promise.allSettled.
  • Dependent calls: run the second after the first (enabled flag or an await chain).

  5. Slow network: parallel calls, caching, pagination, debounce, backend profiling.
  6. Memory growth: leaks (missing cleanup).
  7. Fix the highest-impact item first, then re-measure, and add a performance budget/CI check to prevent regressions.

Structure to say in an interview: “Measure → find the bottleneck → fix → verify.” Randomly adding useMemo is the wrong approach.

126What is a Closure?

What: when an inner function remembers the variables of its outer function, even after the outer function has finished. Function + its lexical environment = closure.

Why: private data, keeping state, function factories, and patterns like debounce/memoize/once.

function createCounter() {
  let count = 0;                 // private variable
  return () => ++count;
}
const counter = createCounter();
counter(); // 1
counter(); // 2

Common uses: data hiding, once(fn), debounce, counters, event handlers, React hooks (useState remembers state through closures).

Classic bug:

function Timer() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setCount(count + 1), 1000);
    return () => clearInterval(id);
  }, []);
}

Downsides: too many closures, or big objects held in references, cause memory leaks. In React, the stale-closure bug.

127What is Hoisting?

What: the behaviour where, before execution, declarations seem to be “moved to the top” of their scope (the memory creation phase).

console.log(a);
var a = 5;

console.log(b);  // ReferenceError (TDZ - Temporal Dead Zone)
let b = 5;

greet();
function greet() { console.log("Hi"); }

sayHi();
var sayHi = function () {};

Summary: var → hoisted + undefined. let/const → hoisted but in the TDZ (access error). Function declaration → fully hoisted. Function expression/arrow → follows the variable’s rules.

129What is a Promise?

What: an object that represents a value that will arrive in the future (success or failure). 3 states: pending, fulfilled, rejected.

const getStock = id => new Promise((resolve, reject) => {
  setTimeout(() => (id ? resolve({ id, stock: 12 }) : reject(new Error("ID missing"))), 500);
});

getStock(1)
  .then(res => console.log(res))
  .catch(err => console.error(err))
  .finally(() => console.log("done"));

Why: to escape callback hell (nested callbacks) and to get chaining and error handling. Combinators: Promise.all/allSettled/race/any.

130What is Async/Await?

What: syntax (syntactic sugar) for writing promise code that looks synchronous. An async function always returns a Promise; await waits until the Promise resolves (the rest of the program is not blocked).

async function loadDashboard() {
  try {
    const [user, orders] = await Promise.all([getUser(), getOrders()]);
    return { user, orders };
  } catch (err) {
    console.error("Failed", err);
    throw err;
  }
}

Common mistakes:

  • Awaiting independent calls one after another (slow); use Promise.all.
  • useEffect(async () => ...): no; define an async function inside and call it.
  • await inside forEach does not work; use for...of or Promise.all(map).
131What is the Event Loop?

What: JS is single-threaded; the Event Loop is the mechanism that, when the call stack is empty, picks tasks from the queues and runs them, so async work (timers, network) does not block.

Order:

  1. Run the synchronous code on the Call Stack.
  2. When the stack is empty → drain the Microtask queue (Promise .then, async/await, queueMicrotask).
  3. Then one Macrotask (setTimeout, setInterval, DOM events, I/O).
  4. Repeat (rendering happens in between).
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2

Why: microtasks run before macrotasks, which is why Promise.then comes before setTimeout(0). A heavy synchronous loop freezes the UI (it blocks the event loop).

132What is the Call Stack?

What: a LIFO (Last In First Out) structure that tracks which function is currently executing and where to return. On a function call it is pushed, on return it is popped.

function a() { b(); }
function b() { c(); }
function c() { console.log("done"); }
a();
// Stack: [a] -> [a, b] -> [a, b, c] -> pop c -> pop b -> pop a

Stack overflow: infinite/very deep recursion fills the stack (RangeError: Maximum call stack size exceeded). In debugging, the DevTools “Call Stack” panel shows exactly this.

133What is the Microtask Queue?

What: a high-priority queue that holds Promise callbacks (.then/.catch/.finally), the code after await, queueMicrotask, MutationObserver. As soon as the current stack is empty, the whole microtask queue runs before the next macrotask.

setTimeout(() => console.log("macro"), 0);
Promise.resolve().then(() => console.log("micro"));
// micro, macro

Gotcha: if a microtask keeps creating new microtasks, macrotasks (and rendering) starve.

134Write Debounce and Throttle code.
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

function throttle(fn, limit) {
  let inThrottle = false;
  return function (...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}

const onSearch = debounce(q => fetchResults(q), 400);
window.addEventListener("scroll", throttle(checkPosition, 200));

In React: a re-render creates a new debounced function. Use useMemo/useRef, or a useDebounce hook (Q32). A closure is what makes all this work (the timer variable is remembered).

135Explain map(), filter(), reduce().

All three array methods return a new result (they do not mutate the original array).

const products = [
  { id: 1, name: "Shoes", price: 2000, qty: 2, inStock: true },
  { id: 2, name: "Bag", price: 1500, qty: 1, inStock: false },
  { id: 3, name: "Watch", price: 5000, qty: 1, inStock: true },
];

const names = products.map(p => p.name);                    // ["Shoes","Bag","Watch"]

const available = products.filter(p => p.inStock);          // Shoes, Watch

const total = products.reduce((sum, p) => sum + p.price * p.qty, 0);   // 8500

// Chain
const payable = products.filter(p => p.inStock).map(p => p.price * p.qty).reduce((a, b) => a + b, 0);

In React: map to render lists, filter for search/remove, reduce for cart totals/group by. Always give reduce an initial value, otherwise it errors on an empty array.
