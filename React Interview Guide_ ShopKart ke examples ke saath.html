React Fundamentals 10 sawaal

1React kya hai?

What: React ek open-source JavaScript library hai jo user interface (UI) banane ke liye use hoti hai. Meta (Facebook) ne 2013 mein launch ki. Iska main idea hai: poori screen ko chhote-chhote reusable components mein tod do aur data change hone par React khud UI update kar de.

Why: Pehle jab hum plain JavaScript/jQuery se UI banate the, to har baar data change hone par manually document.getElementById(...).innerText = ... likhna padta tha. Badi app mein ye bugs ka ghar ban jata tha (“cart count update hua par header mein nahi hua”).

How: React mein hum bolte hain “UI kaisa dikhna chahiye is data ke liye” (declarative), aur “kaise update karna hai” React sambhalta hai.

Real project example (ShopKart): Product card, Navbar, Cart, Filter sidebar - sab alag components. Cart mein item add hua to cartCount state badla, aur Navbar ka badge, Cart page aur checkout summary - teeno automatically update ho gaye.

function Navbar({ cartCount }) {
  return <header>ShopKart 🛒 {cartCount}</header>;
}

Interview line: “React ek declarative, component-based library hai jo state ke basis par UI render karti hai aur Virtual DOM se efficient updates karti hai.”

2React ke features kya hain?

Main features:

  • Component-based architecture: UI ko chhote independent pieces mein todna. Reuse aur testing aasan.
  • Virtual DOM: Real DOM ka lightweight copy; sirf changed part update hota hai.
  • JSX: JS ke andar HTML jaisa syntax.
  • One-way data flow: Data parent se child ki taraf (props). Debug karna easy.
  • Hooks: Functional components mein state aur lifecycle.
  • Huge ecosystem: React Router, Redux Toolkit, React Query, Next.js.
  • Declarative: “Kya dikhana hai” likho, “kaise” React dekhega.

Why ye features important hain: Ek team mein 10 developers kaam kar rahe hon to alag-alag components par parallel kaam ho sakta hai. ShopKart mein ek developer ProductCard bana raha hai, doosra Checkout - bina ek doosre ki file touch kiye.

4React library hai ya framework?

Answer: Library. Kyunki React sirf View layer sambhalti hai - UI render karna. Routing, API calls, form validation, global state ke liye ye koi rule nahi deti.

Why ye matter karta hai: Framework “Hollywood principle” follow karta hai - “hum tumhe call karenge, tum structure follow karo”. Library mein aap us par control rakhte ho.

Real example: ShopKart mein humne React + React Router (routing) + Redux Toolkit (state) + Axios (API) + React Hook Form (forms) joda. Ye “stack” banane ki freedom library deti hai. Next.js jaise tools React ke upar framework ban jate hain (SSR, routing built-in).

5SPA (Single Page Application) kya hai?

What: Aisi web app jisme browser sirf ek HTML page load karta hai, aur page change karte waqt poora page reload nahi hota; JavaScript sirf zaroori hissa badal deta hai.

Why: Traditional (MPA) websites mein har click par server se naya HTML aata hai - flicker, slow. SPA mein feel app jaisa aata hai (Gmail, Instagram web).

How: Server ek index.html + JS bundle deta hai. React Router URL dekh kar decide karta hai kaun sa component dikhana hai. Data chahiye to API call (JSON).

ShopKart example: /products se /cart par jate hi header, footer wahi rehte hain, sirf beech ka content badalta hai. Music player ya cart state bhi bina reload bacha rehta hai.

Downside: Initial load heavy ho sakta hai aur SEO challenge (isliye SSR/Next.js ya prerendering use hota hai).

6Virtual DOM kya hai?

What: Real DOM ka JavaScript object copy jo memory mein rehta hai. Ye bahut halka hota hai kyunki ismein actual browser painting nahi hoti.

Why: Real DOM update karna costly hai (layout, repaint). Agar har chhote change par poora DOM badla jaye to app slow ho jayegi.

How (step by step):

  1. State change hota hai.
  2. React naya Virtual DOM tree banata hai.
  3. Purane aur naye tree ko compare karta hai (diffing).
  4. Sirf jo different hai, wahi real DOM mein apply hota hai (patch).

Real example: ShopKart ki 50 products ki list hai. Ek product ka price change hua. React sirf us ek price ka text node update karega, baaki 49 cards touch nahi honge.

// Aap sirf state badalte ho, DOM React sambhalta hai
const [price, setPrice] = useState(999);
<p>₹{price}</p>

8JSX kya hai?

What: JSX = JavaScript XML. JS ke andar HTML jaisa syntax likhne ka tareeka. Ye actual HTML nahi hai; compile hone par React.createElement() (ya modern jsx()) calls ban jati hain.

Why: UI aur uska logic ek jagah rehta hai (separation of concerns by feature, not by file type). Readable code.

Rules:

  • Ek hi parent element return karo (ya Fragment <>...</>).
  • class ki jagah className, for ki jagah htmlFor.
  • JS expression { } ke andar.
  • Har tag close hona chahiye (<img />).
function ProductCard({ product }) {
  return (
    <div className="card">
      <h3>{product.name}</h3>
      <p>₹{product.price}</p>
      {product.stock === 0 && <span>Out of stock</span>}
    </div>
  );
}

Security bonus: JSX by default values ko escape karta hai, to XSS ka risk kam hota hai.

9JSX kyu use karte hain?
  • Readability: React.createElement('div', {className:'card'}, ...) nested likhna dard hai. JSX visual structure dikhata hai.
  • Logic + UI together: Conditional, loops sab JS se.
  • Compile-time errors: Galat tag likha to build time par pata chal jata hai.
  • Tooling: ESLint, TypeScript, Prettier ka support.

Mandatory nahi hai - React JSX ke bina bhi chal sakti hai, par practically 100% projects JSX use karte hain.

10Babel kya hai?

What: Babel ek JavaScript compiler/transpiler hai. Ye modern JS/JSX ko aise JS mein badalta hai jo browsers samajh sakein.

Why: Browser JSX nahi samajhta. Purane browsers ES6+ features (arrow function, optional chaining) bhi na samjhein.

How: Build tool (Vite/webpack) ke andar chalta hai.

// Aap likhte ho
const el = <h1 className="title">Hello</h1>;
// Babel ye bana deta hai
const el = React.createElement("h1", { className: "title" }, "Hello");

Real note: Aaj kal Vite (esbuild/SWC) bhi use hota hai, jo Babel se fast hai; concept same hai: JSX → JS.

Components 7 sawaal

11Functional Component kya hai?

What: Ek simple JavaScript function jo JSX return karta hai. Modern React mein 99% components yehi hote hain.

Why: Kam code, easy to read, Hooks ke saath state aur lifecycle bhi mil jata hai. this ka confusion nahi.

function CartBadge({ count }) {
  return <span className="badge">{count}</span>;
}

Real example: ShopKart ka CartBadge, Button, PriceTag, Rating - sab functional components.

12Class Component kya hai?

What: ES6 class jo React.Component extend karti hai, render() method JSX return karta hai. State this.state, update this.setState().

class Counter extends React.Component {
  state = { count: 0 };
  componentDidMount() { document.title = "Loaded"; }
  render() {
    return <button onClick={() => this.setState({ count: this.state.count + 1 })}>
      {this.state.count}
    </button>;
  }
}

Aaj kyu aana chahiye: Purane codebases (legacy) mein milte hain, aur Error Boundaries abhi bhi class component se hi banti hain (hooks equivalent nahi hai). Naye code mein functional use karo.

14Pure Component kya hai?

What: Aisa component jo sirf tab re-render hota hai jab uske props ya state ki shallow comparison mein change aaye. Class mein React.PureComponent, functional mein React.memo.

Pure function idea: Same input → same output, koi side effect nahi.

Why: Parent re-render hone par bhi child ko bekaar mein re-render hone se bachana.

const ProductCard = React.memo(function ProductCard({ product }) {
  console.log("render", product.id);
  return <div>{product.name}</div>;
});

Dhyan rakho: Shallow comparison hai. Agar aap har render par naya object/array/function props mein dete ho, to memo kaam nahi karega (see useCallback, useMemo).

15Higher Order Component (HOC) kya hai?

What: Ek function jo component leta hai aur naya enhanced component return karta hai.

Why: Cross-cutting logic (auth check, logging, loader) ko baar-baar copy na karna pade.

function withAuth(Component) {
  return function Protected(props) {
    const { user } = useAuth();
    if (!user) return <Navigate to="/login" />;
    return <Component {...props} user={user} />;
  };
}
const AdminDashboard = withAuth(Dashboard);

Real example: ShopKart mein withAuth, withLoader. Examples libraries: connect() (old Redux), React.memo.

Aaj ka scene: Custom hooks aur wrapper components zyada pasand kiye jate hain kyunki HOC se “wrapper hell” aur prop collisions hote hain.

16Presentational aur Container Components kya hain?

Presentational: Sirf UI dikhata hai, props se data leta hai, API/state ka pata nahi. Container: Data fetch karta hai, state manage karta hai, presentational ko props deta hai.

// Container
function ProductListContainer() {
  const { data, isLoading } = useProducts();
  if (isLoading) return <Spinner />;
  return <ProductList products={data} />;
}
// Presentational
function ProductList({ products }) {
  return products.map(p => <ProductCard key={p.id} product={p} />);
}

Why: Testing aur reuse easy. Designer UI part par kaam kare, developer logic par. Aaj hooks ke baad ye pattern formal rule nahi, “custom hook + UI” ke roop mein chalta hai.

17Reusable Components kaise banate ho?

Principles:

  1. Single responsibility: Ek component ek kaam.
  2. Props se customize: Hard-coded text/color nahi.
  3. Composition (children): Andar kuch bhi daal sako.
  4. Sensible defaults.
  5. Logic ko hook mein, UI ko component mein.
function Button({ variant = "primary", loading = false, children, ...rest }) {
  return (
    <button className={`btn btn-${variant}`} disabled={loading || rest.disabled} {...rest}>
      {loading ? "Please wait..." : children}
    </button>
  );
}
// Use
<Button variant="danger" onClick={removeItem}>Remove</Button>
<Button loading={isPaying}>Pay Now</Button>

Real example: ShopKart mein ek Modal, Table, Input, Button ka shared UI library (/components/ui). Login, checkout, admin sab ek hi Button use karte hain; design change ek jagah se.

Props & State 7 sawaal

18Props kya hain?

What: Props = properties. Parent se child ko pass kiya jaane wala read-only data. Child unhe modify nahi kar sakta.

Why: Component ko reusable banata hai. Same ProductCard alag-alag data se alag products dikha sakta hai.

<ProductCard name="Nike Shoes" price={4999} inStock />
function ProductCard({ name, price, inStock }) { ... }

Rule: Props immutable hain. Child ko change chahiye to parent se function prop (callback) maangta hai.

19State kya hai?

What: Component ki apni private memory jo time ke saath change hoti hai. State badalne par React component ko re-render karta hai.

Why: Normal variable change hone par UI update nahi hota; state change React ko signal deta hai.

function Quantity() {
  const [qty, setQty] = useState(1);
  return (
    <>
      <button onClick={() => setQty(q => Math.max(1, q - 1))}>-</button>
      <span>{qty}</span>
      <button onClick={() => setQty(q => q + 1)}>+</button>
    </>
  );
}

Rules: State ko seedha mutate mat karo (arr.push galat). Hamesha setter use karo aur naya object/array banao.

20Props and State mein difference?
Props State
Bahar se aata hai (parent se) Component ke andar ka
Read-only Setter se change hota hai
Child modify nahi kar sakta Component khud modify karta hai
Config ki tarah Memory ki tarah

Real example: ProductCard ko product props milta hai (parent decide karta hai), lekin “wishlist heart filled hai ya nahi” useState mein hota hai (card ka apna).

Thumb rule: Agar data parent se aa raha hai aur change nahi karna → props. Agar user interaction se badalta hai aur UI par asar padta hai → state. Agar kisi aur state se nikal sakta hai → derived value (state mat banao).

21State update asynchronous kyu hota hai?

Reason (performance): React multiple setState calls ko batch karta hai aur ek hi baar re-render karta hai. Isliye setCount(count + 1) ke turant baad count purani value hi dikhata hai - us render ka count ek “snapshot” hai.

const [count, setCount] = useState(0);
function handle() {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
  console.log(count); // 0 (purana)
}                     // final: 1, 3 nahi!

// Sahi: functional update
function handleCorrect() {
  setCount(c => c + 1);
  setCount(c => c + 1);
  setCount(c => c + 1);   // final: 3
}

Real bug: ShopKart mein “Add to cart” par quick double click karne se quantity 1 hi badhi - kyunki stale value use ki thi. Fix: setQty(q => q + 1). Latest value chahiye to useEffect ya flushSync (rare) use karo. React 18 mein batching timeouts/promises mein bhi hoti hai.

22Parent to Child data pass kaise karte ho?

Props se. Simple aur most common way.

function ProductPage() {
  const product = { id: 1, name: "Laptop", price: 55000 };
  return <ProductCard product={product} onBuy={() => alert("Buy")} />;
}
function ProductCard({ product, onBuy }) {
  return <div>{product.name} <button onClick={onBuy}>Buy</button></div>;
}

Deep levels par data bhejna ho to Context API ya state management (prop drilling se bachne ke liye).

23Child to Parent data pass kaise karte ho?

React mein data upar nahi jata; parent ek callback function props mein deta hai aur child usse call karta hai.

function Parent() {
  const [filter, setFilter] = useState("");
  return (
    <>
      <FilterBar onChange={setFilter} />
      <ProductList filter={filter} />
    </>
  );
}
function FilterBar({ onChange }) {
  return <input onChange={e => onChange(e.target.value)} placeholder="Search" />;
}

Real example: ShopKart mein FilterSidebar (child) user ne category choose ki → parent ProductsPage ko batata hai → parent API query update karta hai. Is technique ko “lifting state up” bhi kehte hain.

24Prop Drilling kya hai?

What: Data ko kai levels ke components se guzar kar bhejna jabki beech ke components ko us data ki zaroorat hi nahi.

// App -> Layout -> Header -> UserMenu -> Avatar  (user har jagah pass)
<Layout user={user} /> -> <Header user={user} /> -> <UserMenu user={user} />

Problem: Code verbose, refactor mushkil, beech ke components bekaar re-render.

Solutions:

  1. Context API (theme, user, language).
  2. Redux Toolkit / Zustand (bada shared state).
  3. Component composition (children pass karke drilling skip).
  4. Server-state ke liye React Query.

ShopKart example: Logged-in user ko 5 level neeche Avatar ko chahiye. AuthContext banaya, Avatar mein useAuth() call kiya. Beech ke components ko props nahi chahiye. Par har chhote 2-3 level ke kaam ke liye Context mat lagao - drilling 2-3 level tak theek hai.

Hooks 11 sawaal

25Hooks kya hain?

What: Hooks special functions hain (naam use... se shuru) jo functional components mein state, lifecycle aur React features “hook” karne dete hain. React 16.8 mein aaye.

Why aaye: Class components mein logic reuse karna mushkil tha (HOC/render props), this confusing tha, aur ek feature ka code alag-alag lifecycle methods mein bikhra hota tha.

Rules of Hooks:

  1. Sirf top level par call karo (if/loop/nested function ke andar nahi).
  2. Sirf React function components ya custom hooks mein call karo.

Why rules: React hooks ko call order se yaad rakhta hai. Condition mein hook daloge to order bigad jayega aur state galat hook se mil jayegi.

Common hooks: useState, useEffect, useRef, useMemo, useCallback, useContext, useReducer, useLayoutEffect, useTransition, useId.

26useState kya hai?

What: Component mein state rakhne ka hook. [value, setValue] = useState(initial).

function SearchBox() {
  const [query, setQuery] = useState("");
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}

Important points:

  • Lazy initial state: Expensive init ho to function do: useState(() => JSON.parse(localStorage.getItem("cart")) ?? []) - ye sirf pehle render par chalega.
  • Functional update: setCount(c => c + 1) jab new value old par depend kare.
  • Objects/arrays immutable update:
setCart(prev => [...prev, newItem]);                       // add
setCart(prev => prev.filter(i => i.id !== id));            // remove
setCart(prev => prev.map(i => i.id === id ? { ...i, qty: i.qty + 1 } : i)); // update

Same value set karo (Object.is equal) to React re-render skip kar deta hai.

27useEffect kya hai?

What: Side effects run karne ka hook: API call, subscription, timer, DOM manipulation, localStorage, event listener. Render ke baad chalta hai.

Why: Render function “pure” hona chahiye. API call jaisa kaam render ke andar nahi kar sakte; effect mein karte hain.

Syntax:

useEffect(() => {
  // effect (setup)
  return () => { /* cleanup */ };
}, [dependencies]);

Real example - ShopKart product details:

function ProductDetails({ productId }) {
  const [product, setProduct] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(`/api/products/${productId}`, { signal: controller.signal })
      .then(r => { if (!r.ok) throw new Error("Failed"); return r.json(); })
      .then(setProduct)
      .catch(e => { if (e.name !== "AbortError") setError(e.message); })
      .finally(() => setLoading(false));

    return () => controller.abort();   // user doosre product par gaya to purani request cancel
  }, [productId]);                     // productId badla to dobara chalega
  ...
}

Tip: Sirf data fetching ke liye real projects mein React Query/RTK Query behtar hai (cache, retry, dedupe).

28useRef kya hai?

What: Ek mutable box ({ current: value }) jo re-renders ke beech same rehta hai, aur jise badalne par re-render nahi hota.

Do main use cases:

  1. DOM element access: focus, scroll, video play.
  2. Value yaad rakhna bina render trigger kiye: timer id, previous value, “is mounted” flag.
function LoginForm() {
  const emailRef = useRef(null);
  useEffect(() => { emailRef.current.focus(); }, []);   // page open hote hi focus
  return <input ref={emailRef} type="email" />;
}

function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; });
  return ref.current;
}

useState vs useRef: State badle to UI update chahiye; ref badle to UI se matlab nahi (e.g. debounce timer id).

29useMemo kya hai?

What: Expensive calculation ka result cache karta hai; dependencies na badle to dobara calculate nahi karta.

const filtered = useMemo(
  () => products.filter(p => p.name.toLowerCase().includes(query.toLowerCase()))
                 .sort((a, b) => a.price - b.price),
  [products, query]
);

Why: 10,000 products ko har keypress aur har unrelated state change par filter+sort karna wasteful hai.

Doosra use: Object/array ki reference stable rakhna taaki React.memo child unnecessary re-render na ho.

Warning: Har jagah mat lagao. Memo khud bhi cost lagata hai. Pehle measure (React Profiler) karo. Ye “performance hint” hai, semantic guarantee nahi.

30useCallback kya hai?

What: Function ki reference cache karta hai (useMemo(() => fn, deps) ka shortcut).

Why: Component re-render hone par har baar naya function banta hai; React.memo wala child ko lagta hai prop badal gaya, to wo bhi re-render.

const ProductCard = React.memo(({ product, onAdd }) => { ... });

function ProductList({ products }) {
  const [cart, setCart] = useState([]);
  const handleAdd = useCallback(id => {
    setCart(prev => [...prev, id]);       // functional update -> deps khaali
  }, []);
  return products.map(p => <ProductCard key={p.id} product={p} onAdd={handleAdd} />);
}

Yaad rakho: useCallback tabhi fayda deta hai jab child React.memo ho (ya function kisi hook dependency mein ho). Akela use karna kuch nahi karta.

31useContext kya hai?

What: Context se data ko kisi bhi depth ke component mein seedha padhne ka hook, prop drilling ke bina.

const ThemeContext = createContext("light");

function App() {
  const [theme, setTheme] = useState("light");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Header />
    </ThemeContext.Provider>
  );
}
function ThemeToggle() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>{theme}</button>;
}

Dhyan: Jab Provider ki value badalti hai, saare consumers re-render hote hain. Isliye frequently-changing data ko Context mein mat rakho; context ko chhote-chhote (Auth, Theme, Cart) mein baant do, aur value ko useMemo karo.

32Custom Hook kya hai?

What: Aapka banaya hua function jiska naam use se shuru ho aur jo andar dusre hooks use kare. Logic reuse karne ka tareeka.

Why: 5 components mein same “fetch + loading + error” ya “localStorage sync” code copy-paste karne se achha ek hook.

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try { return JSON.parse(localStorage.getItem(key)) ?? initial; }
    catch { return initial; }
  });
  useEffect(() => { localStorage.setItem(key, JSON.stringify(value)); }, [key, value]);
  return [value, setValue];
}

function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

ShopKart hooks: useAuth(), useCart(), useDebounce(), useOnlineStatus(), useProducts(). Har hook ka state alag hota hai (share nahi hota).

33useReducer kya hai?

What: useState ka advanced version jahan state update ka logic ek reducer function (state, action) => newState mein rehta hai.

Kab use karein: Jab state complex ho (multiple related fields) ya next state previous par depend kare. Cart, multi-step form, checkout flow.

function cartReducer(state, action) {
  switch (action.type) {
    case "ADD": {
      const exists = state.items.find(i => i.id === action.item.id);
      return {
        ...state,
        items: exists
          ? state.items.map(i => i.id === action.item.id ? { ...i, qty: i.qty + 1 } : i)
          : [...state.items, { ...action.item, qty: 1 }],
      };
    }
    case "REMOVE": return { ...state, items: state.items.filter(i => i.id !== action.id) };
    case "CLEAR":  return { items: [] };
    default: return state;
  }
}

const [state, dispatch] = useReducer(cartReducer, { items: [] });
dispatch({ type: "ADD", item: product });

Why: Saari update logic ek jagah, test karna easy (pure function), aur dispatch ki identity stable hoti hai.

36useEffect lifecycle explain karo.

Functional component ka flow:

  1. Render: Component function chalta hai, JSX banta hai.
  2. Commit: React DOM update karta hai.
  3. Paint: Browser screen par dikhata hai.
  4. Effect run: useEffect ka callback chalta hai.
  5. Agar dependency badli: pehle purana cleanup, phir naya effect.
  6. Unmount par: cleanup chalta hai.

Class lifecycle se mapping:

Class useEffect
componentDidMount useEffect(fn, [])
componentDidUpdate useEffect(fn, [dep])
componentWillUnmount return () => {} cleanup 
useEffect(() => {
  console.log("Mounted ya productId badla:", productId);
  return () => console.log("Cleanup:", productId);
}, [productId]);

Strict Mode (development): React 18+ dev mein component ko mount → unmount → mount karke check karta hai ki cleanup sahi hai. Isliye effect 2 baar chalta dikhta hai (production mein nahi). Bug nahi hai; ye aapko galat cleanup pakadne mein madad karta hai.

42React.memo kya hai?

46Re-render kyu hota hai?

Component tab re-render hota hai jab:

  1. Apni state badli (setState).
  2. Parent re-render hua (chahe props same hon, jab tak memo na ho).
  3. Props badle.
  4. Context value badli (jo context consume karta hai).
  5. Custom hook ke andar ki state badli (wo bhi component ki state hai).

Galat dharna: “Props badle tabhi child render hota hai” - nahi, parent render hua to child bhi hota hai (default). Re-render ka matlab function dobara chalna, DOM update zaroori nahi. React diff karke DOM tabhi chhoota hai jab output badla ho.

47Unnecessary re-renders kaise avoid karte ho?
  1. State ko jahan chahiye wahin rakho (colocation): Search input ka state alag SearchBox component mein, poore page mein nahi.
  2. React.memo + stable props (useCallback, useMemo).
  3. Children pattern:
function Timer({ children }) {
  const [time, setTime] = useState(0);   // sirf Timer re-render hoga
  return <div>{time}{children}</div>;     // children ka element already bana hai
}
  1. Context split: UserContext aur ThemeContext alag; theme badle to user consumers ko asar nahi.
  2. Selectors (Redux): useSelector(s => s.cart.items.length) - poora store nahi.
  3. Key sahi do, inline objects/arrays se bacho (jab memo child ho).
  4. Derived state ko state mein mat daalo; render ke time calculate karo.
  5. Debug: React DevTools > “Highlight updates”, Profiler, why-did-you-render.
48Debouncing kya hai?

What: Function ko tab chalana jab user kuch delay tak ruk jaye. Beech ke saare calls ignore.

Why: Search box mein “iphone” type kiya to 6 API calls (i, ip, iph…) bekaar. Debounce se user ke ruke par ek call.

function Search() {
  const [q, setQ] = useState("");
  const debounced = useDebounce(q, 500);

  useEffect(() => {
    if (!debounced) return;
    const controller = new AbortController();
    fetch(`/api/search?q=${debounced}`, { signal: controller.signal })
      .then(r => r.json()).then(setResults).catch(() => {});
    return () => controller.abort();
  }, [debounced]);

  return <input value={q} onChange={e => setQ(e.target.value)} />;
}

Use cases: Search/autocomplete, form auto-save, window resize handler.

49Throttling kya hai?

What: Function ko fixed time interval mein maximum ek baar chalne dena, chahe event kitni bhi baar aaye.

Debounce vs Throttle:

  • Debounce: “ruko, jab user shaant ho tab chalo.”
  • Throttle: “har 300ms mein ek baar chalo, chahe user chalta rahe.”

Use cases: Scroll (infinite scroll position check), mouse move, resize, “Like” button spam rokna, analytics events.

function throttle(fn, limit) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= limit) { last = now; fn(...args); }
  };
}
window.addEventListener("scroll", throttle(checkLoadMore, 300));

Why: Initial bundle chhota → app jaldi khulti hai (better LCP).

51Code Splitting kya hai?

Rendering 6 sawaal

52Rendering kya hai?

What: Rendering = React ka component function chalakar JSX/UI description banana aur phir use screen par dikhana.

Do phases:

  1. Render phase: Component functions chalte hain, naya Virtual DOM tree banta hai (pure calculation, koi DOM touch nahi).
  2. Commit phase: React diff ke hisaab se real DOM update karta hai. Effects yahin ke baad chalte hain.

Initial render (app pehli baar) aur re-render (state/props change). Server-side rendering (SSR) mein ye server par hota hai aur HTML bhej diya jata hai.

Yaad rakho: Render function pure hona chahiye (same input → same output); usme API call, Math.random(), ya DOM change nahi.

53Re-render kab hota hai?

54Conditional Rendering kya hai?

What: Condition ke basis par alag UI dikhana.

function ProductList({ products, loading, error }) {
  if (loading) return <Skeleton />;                 // 1. early return
  if (error) return <ErrorMessage text={error} />;
  if (!products.length) return <p>Koi product nahi mila</p>;

  return (
    <>
      {products.map(p => <ProductCard key={p.id} product={p} />)}

56Key prop kyu use karte ho?

What: key ek special prop hai jo React ko batata hai ki list ka kaun sa item kaun sa hai.

Why: Reconciliation ke time React purani aur nayi list compare karta hai. Key se wo samajhta hai: item add hua, remove hua ya sirf move hua - aur existing components reuse karta hai. Bina key ke poori list re-create ya galat update ho sakti hai.

How:

{cart.map(item => <CartItem key={item.id} item={item} />)}

Real bug: Cart mein 3 items, har item mein quantity input hai. Pehla item delete kiya, magar key index thi - to dusre item ke input mein pehle wali quantity dikh gayi. Key item.id karne par theek hua. Key props mein nahi aati (props.key undefined).

57Index ko key kyu avoid karte ho?

Jab list reorder, insert, delete, ya filter hoti hai, index badal jata hai. React same index wale component ko “wahi item” samajh leta hai, to state aur DOM galat item se chipak jate hain.

// Galat (dynamic list ke liye)

// Sahi
items.map(item => <Row key={item.id} item={item} />)

Event Handling 4 sawaal

64Event Handling kya hai?

User actions (click, type, submit, hover) par function chalana. React mein events camelCase hote hain aur function pass karte hain (string nahi).

<button onClick={handleAddToCart}>Add</button>          // sahi
<button onClick={handleAddToCart()}>Add</button>        // galat: render par hi chal jayega
<button onClick={() => handleAdd(product.id)}>Add</button> // argument ke saath

e.preventDefault() form submit/link default roke, e.stopPropagation() bubbling roke.

65Synthetic Event kya hai?

What: React ka cross-browser wrapper jo native browser event ke upar banta hai (SyntheticEvent). Interface same rehta hai: e.target, e.preventDefault(), e.stopPropagation().

Why: Alag browsers ke event differences React chhupa deta hai.

Event delegation: React har element par listener nahi lagata; root par ek listener lagakar events handle karta hai (efficient). Native event chahiye to e.nativeEvent.

Note: React 16 tak event pooling thi (async access par event null ho jata), React 17+ mein pooling hata di gayi.

66onClick aur onChange ka use?
  • onClick: Click par (button, card, link).
  • onChange: Input ki value badalne par (har keystroke, select, checkbox). Controlled input ka core.
function QuantityInput() {
  const [qty, setQty] = useState(1);
  return (

  );
}

67Event bubbling kya hai?

Event pehle target element par chalta hai, phir upar parent ki taraf bubble hota hai.

<div onClick={() => console.log("Card clicked")}>
  <button onClick={e => { e.stopPropagation(); addToCart(); }}>Add to cart</button>

76Context API kya hai?

What: React ka built-in mechanism jisse data ko component tree ke kisi bhi level par bina props pass kiye share kar sakte hain.

Three steps: createContext → Provider (value dena) → useContext (value lena).

const AuthContext = createContext(null);

}

export const useAuth = () => {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth AuthProvider ke andar use karo");
  return ctx;
};

80Redux kya hai?

What: Predictable state container. Poori app ka state ek central store mein hota hai aur sirf actions → reducers ke through badal sakta hai.

Why: Badi app mein state kai jagah bikhra ho to “kisne ye value badli” pata nahi chalta. Redux mein har change traceable hai (Redux DevTools mein har action dikhta hai).

  4. Reducer naya cart state banata hai.
  5. Store update hota hai; useSelector(selectCartCount) use karne wale components (Navbar badge, Cart page) re-render.

Ye unidirectional data flow hai - isliye bug trace karna aasan.

84Reducer kya hai?

What: Pure function (state, action) => newState. Action dekh kar naya state return karta hai.

86Middleware kya hai?

87Redux Toolkit kya hai?

What: Redux ka official, recommended tareeka. Boilerplate kam karta hai aur best practices default mein deta hai.

  • createEntityAdapter, RTK Query (data fetching + caching)

88createSlice kya hai?

What: State ka ek hissa (slice) define karne ka function: name, initialState, reducers. Actions aur reducer automatically ban jate hain.

import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",
  initialState: { items: [] },
  reducers: {
    addToCart(state, action) {
      const item = state.items.find(i => i.id === action.payload.id);
      if (item) item.qty += 1;                        // Immer: mutate allowed
      else state.items.push({ ...action.payload, qty: 1 });
    },
    removeFromCart(state, action) {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
    clearCart: state => { state.items = []; },
  },
});

export const { addToCart, removeFromCart, clearCart } = cartSlice.actions;
export default cartSlice.reducer;
export const selectCartCount = s => s.cart.items.reduce((n, i) => n + i.qty, 0);

90createAsyncThunk kya hai?

    } catch (err) {

  name: "products",
  initialState: { list: [], status: "idle", error: null },
  reducers: {},
  extraReducers: builder => {
    builder

      .addCase(fetchProducts.fulfilled, (s, a) => { s.status = "succeeded"; s.list = a.payload; })
      .addCase(fetchProducts.rejected,  (s, a) => { s.status = "failed"; s.error = a.payload; });

100React mein Login flow kaise implement karte ho?

Flow:

  1. User email/password daalta hai → POST /auth/login.
  2. Server credentials verify karke access token (response) aur refresh token (httpOnly cookie) deta hai.
  3. Frontend user ko state/context mein rakhta hai, access token memory mein.
  4. Har API call mein Authorization: Bearer <token>.
  5. 401 aaye to refresh endpoint se naya token, phir original request retry.
  6. Page refresh par /auth/me ya refresh endpoint se session restore (is dauran loading state).
  7. Logout par server se cookie clear + state clear.
export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    api.get("/auth/me").then(r => setUser(r.data)).catch(() => setUser(null)).finally(() => setLoading(false));
  }, []);

  const login = async creds => {
    const { data } = await api.post("/auth/login", creds);
    setAccessToken(data.accessToken);
    setUser(data.user);
  };
  const logout = async () => { await api.post("/auth/logout"); setAccessToken(null); setUser(null); };

  return <AuthContext.Provider value={{ user, loading, login, logout }}>{children}</AuthContext.Provider>;
}

109Reconciliation kya hai?

What: Wo process jisse React purane aur naye Virtual DOM tree ko compare karke decide karta hai ki real DOM mein minimum kya change karna hai.

Rules (heuristics):

  1. Alag type ke element (div → span, A → B component): purana tree destroy, naya create (state khatam).
  2. Same type: Sirf changed attributes/props update.
  3. List mein key: Items ko pehchanne ke liye.

Real impact: Ek component ko conditional mein alag-alag type se wrap karoge to state reset ho jayegi. Isliye component ke andar component define mat karo (har render par naya type → remount → input focus lost).

110Diffing Algorithm kya hai?

Do trees ke beech differences nikalna. Generic tree diff O(n^3) hota hai - bahut slow. React ne O(n) heuristic algorithm banaya, 2 assumptions par:

  1. Alag type = alag tree. Detail mein tulna nahi, seedha replace.
  2. key se developer batata hai kaun sa child stable hai.

Level-by-level compare hota hai (same level par). Isliye element ko tree mein doosre level par move karoge to React usko move nahi, destroy+create samajhta hai.

111React Fiber kya hai?

What: React 16 ka naya reconciliation engine. Rendering ka kaam chhote units of work (fibers) mein baant diya.

Pehle problem: Purane stack reconciler mein ek baar render shuru hua to poora khatam hone tak rok nahi sakte the; badi tree par UI freeze (typing lag).

Fiber se:

  • Rendering interruptible hai (pause, resume, abort).
  • Priority: User typing/clicks high priority, data update low priority.
  • Concurrent features (useTransition, Suspense) iske upar bane.

Simple analogy: Pehle React ek 1-ghante ka kaam bina break ke karta tha; ab 5-5 minute ke tukde karta hai aur beech mein zaruri kaam (user click) dekh leta hai.

130Async/Await kya hai?

What: Promises ko synchronous jaisa dikhne wala code likhne ka syntax (syntactic sugar). async function hamesha Promise return karta hai; await Promise resolve hone tak wait karta hai (baaki program block nahi hota).

131Event Loop kya hai?

What: JS single-threaded hai; Event Loop wo mechanism hai jo call stack khaali hone par queues se tasks utha kar chalata hai, isliye async kaam (timers, network) bina block kiye hota hai.

Order:

  1. Call Stack ka synchronous code.
  2. Stack khaali → Microtask queue (Promise .then, async/await, queueMicrotask) pura khaali karo.
  3. Phir ek Macrotask (setTimeout, setInterval, DOM events, I/O).
  4. Repeat (beech mein rendering).
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2

Why: Microtasks macrotasks se pehle chalte hain. Isliye Promise.then setTimeout(0) se pehle aata hai. Heavy synchronous loop UI freeze karta hai (event loop block).

132Call Stack kya hai?

What: LIFO (Last In First Out) structure jo track karta hai kaun sa function abhi execute ho raha hai. Function call par push, return par pop.

function a() { b(); }
function b() { c(); }
function c() { console.log("done"); }
a();
// Stack: [a] -> [a, b] -> [a, b, c] -> pop c -> pop b -> pop a

133Microtask Queue kya hai?

// micro, macro

Gotcha: Agar microtask baar-baar naya microtask banata rahe to macrotasks (aur rendering) bhookhe reh jaate hain (starvation).

134Debounce aur Throttle code likho.
// Debounce: last call ke delay ke baad ek baar chalo
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// Throttle: har `limit` ms mein maximum ek baar
function throttle(fn, limit) {
  let inThrottle = false;
  return function (...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}

const onSearch = debounce(q => fetchResults(q), 400);
window.addEventListener("scroll", throttle(checkPosition, 200));

React mein dhyan: Component re-render par naya debounced function ban jata hai. Use useMemo/useRef, ya useDebounce hook (Q32). Closure hi ye sab kaam karta hai (timer variable yaad rakhta hai).
